# Journal 文章发布操作说明

## 用途

下次只需要提供准备发布的文章正文，并说明希望的语气或重点。发布时由助手根据正文拟定标题、整理标签，然后使用 Chrome 中已有的登录态完成文章创建、公开发布和结果确认。

这套流程只针对 Journal 文章发布，不涉及代码修改、构建、部署或生产环境操作。

## 页面路径

生产站点：`https://feeds.xmcloud.buzz`

| 用途 | 路径 |
| --- | --- |
| 新建文章 | `/me/articles/new` |
| 编辑已保存文章 | `/me/articles/:id/edit` |
| 公开文章 | `/p/:publicId` |
| 公开文章频道 | `/?channel=article` |

## 下次提供给助手的内容

最短输入可以只有：

```text
请发布下面这篇文章：

正文……
```

如果有额外要求，可以一并说明：

- 文章语气：轻快、教程、复盘、随笔等；
- 面向读者：开发者、普通用户或自己的项目访客；
- 必须保留的标题、关键词或标签；
- 是否需要封面图或文中图片。

未指定时，助手根据正文拟定一个不超过 120 字的标题，并生成不超过 20 个、每个不超过 32 字的标签。默认不上传图片。

## 发布流程

1. 阅读用户提供的正文，结合项目源码确认文章中提到的功能与名称。
2. 使用 Chrome 浏览器中的现有登录态打开 `/me/articles/new`。
3. 填写标题、富文本正文和标签。文章编辑器支持 H2、H3、列表、引用、代码、链接及图片。
4. 点击“保存文章”。文章先创建为私有文章，页面会进入 `/me/articles/:id/edit`。
5. 检查标题、正文和标签后，点击“设为公开”。
6. 确认页面显示“可见范围：公开”，再点击“查看文章”。
7. 确认公开页面位于 `/p/:publicId`，并能看到标题、正文和标签；将公开页面留在 Chrome 中，便于用户继续查看。

## 页面与接口对应关系

以下是当前前端实际使用的发布链路，操作时优先通过页面完成：

| 页面动作 | 请求 |
| --- | --- |
| 保存新文章 | `POST /api/me/articles` |
| 保存已有文章 | `PATCH /api/me/articles/:id` |
| 设为公开或转为私有 | `PATCH /api/me/entries/:id/visibility` |
| 查看已保存文章 | `GET /api/me/articles/:id` |

文章创建请求包含 `title`、`richBody` 和 `tags`。文章内容使用 Journal 的富文档格式，不直接拼接 HTML。

## 登录态与权限

- 使用用户当前 Chrome 中已经登录的站点会话。
- 不读取、复制或导出 Cookie、密码及其他登录凭据。
- 如果页面要求登录，停止发布操作，请用户先在 Chrome 中登录后再继续。
- 用户明确要求“发布”时，保存文章和设为公开都属于本次授权范围；如果用户只要求“整理”或“预览”，停在私有文章或预览阶段。

## 操作边界

- 默认新建一篇文章，不覆盖已有文章。
- 默认不上传封面、不上传文中图片、不修改文章发布时间。
- 不因一次发布自动提交代码、构建、部署或修改项目文件。
- 发布完成后以公开页面的实际标题、URL 和公开状态作为结果依据。
- 页面报错时保留错误信息，先定位当前主路径，不在流程中加入重试、降级或静默跳过。
