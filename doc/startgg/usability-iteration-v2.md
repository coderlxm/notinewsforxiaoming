# start.gg 监控易用性迭代方案（V2）

## 1. 目标

本次迭代只服务一个目标：**把使用门槛降到最低，让用户“直接上手就知道做什么”**。  
判断标准不是功能数量，而是“首次配置成功率”和“完成一次监控的操作步数”。

## 2. 当前问题（V1 不合格点）

1. 添加选手要求输入 `player_id`，用户无法直觉获得该值。  
2. 命令数量多，且语义偏技术化。  
3. 缺少“首次使用引导”，用户不知道从哪一步开始。  
4. 失败提示不够可执行（用户不知道下一步该怎么补救）。

## 3. 迭代原则

1. **用户只输入他天然知道的信息**：选手名、start.gg 页面链接。  
2. **命令最小化**：默认只暴露 3 个核心动作。  
3. **对话引导替代文档学习**：首次进入即提示下一步。  
4. **一步一反馈**：每次操作都返回“当前状态 + 下一步”。

## 4. 目标交互（最终体验）

用户只记住这 3 条：

1. `/startgg`  
用途：打开引导面板（现在能做什么）。

2. `/watch <内容>`  
内容可以是：
- 选手名（如：`/watch Tokido`）
- 选手主页链接（如：`/watch https://www.start.gg/user/...`）
- 项目页链接（如：`/watch https://www.start.gg/tournament/.../event/...`）

3. `/watchlist`  
用途：查看监控对象和当前状态摘要。

## 5. 关键能力拆解

## 5.1 选手添加：去 ID 化

### 输入
- `/watch Tokido`

### 系统行为
1. 调用 start.gg API 搜索候选 player。  
2. 若唯一命中：直接添加。  
3. 若多候选：返回序号按钮让用户点选。  
4. 选中后入库仍保存 `player_id`（内部稳定键），但用户无感。

### 输出示例
- `已添加选手：Tokido (日本)；下一步：发送项目链接 /watch <event_url>`

## 5.2 项目添加：只收 URL

### 输入
- `/watch https://www.start.gg/tournament/combo-breaker-2026/event/street-fighter-6`

### 系统行为
1. 从 URL 自动提取 slug。  
2. 校验是否为 event 页面。  
3. 自动解析项目名并入库。

### 输出示例
- `已添加项目：COMBO BREAKER 2026 / Street Fighter 6；当前监控：2 选手 x 1 项目`

## 5.3 首次使用引导

`/startgg` 返回固定结构：
- 你现在还没添加任何监控对象
- 第一步：发送 `/watch <选手名>`
- 第二步：发送 `/watch <项目链接>`
- 完成后系统会自动推送状态变化

不要求用户先读文档。

## 5.4 清晰的错误提示

错误信息必须包含“原因 + 可执行下一步”：

1. 未命中选手  
- `未找到该选手。请改用选手主页链接：/watch https://www.start.gg/user/...`

2. URL 类型不对  
- `这是 tournament 首页，不是 event 页面。请进入具体项目页后再发送链接。`

3. 鉴权失败  
- `start.gg token 无效。请在服务器 .env 更新 STARTGG_API_TOKEN。`

## 6. 数据模型调整

保持现有表不动，最小增量：

1. `startgg_watch_players`
- 新增 `source_input TEXT`：记录用户原始输入（用于追踪体验问题）。

2. 新增 `startgg_watch_pending_choices`
- 用于“多候选选手确认”短时状态。
- 字段：`chat_id`、`query_text`、`candidates_json`、`expires_at`。

## 7. 命令与兼容策略

## 7.1 新命令
- `/startgg`
- `/watch`
- `/watchlist`
- `/unwatch`（可选，V2 同步提供）

## 7.2 旧命令兼容
保留但隐藏（不在帮助里展示）：
- `/startggaddplayer`
- `/startggaddevent`
- `/fetchstartgg`
- `/startggwatchlist`

兼容期建议 2 周，之后按使用情况决定是否下线。

## 8. MVP+ 验收标准（易用性导向）

满足以下条件才算通过：

1. 新用户无需 `player_id` 即可完成“添加 1 选手 + 1 项目”。  
2. 从 `/startgg` 到成功建立监控，操作不超过 3 次消息。  
3. 每个失败场景都有明确下一步提示。  
4. 用户仅靠 `/startgg` 提示可独立完成配置。  
5. `/watchlist` 可一屏展示“监控对象 + 最近状态”。

## 9. 实施顺序

1. 增加 `/startgg` 引导面板。  
2. 新增 `/watch` 路由分流（文本名 / URL）。  
3. 加选手搜索与候选确认。  
4. 接入项目 URL 解析与入库。  
5. 更新 `/watchlist` 输出结构。  
6. 保留旧命令兼容并下沉帮助文本。

## 10. 预期收益

1. 用户不再接触 `player_id`，学习成本显著下降。  
2. 首次配置路径从“查 ID + 填命令”变为“发名字 + 发链接”。  
3. 维护成本可控：核心监控逻辑不变，仅优化输入与引导层。
