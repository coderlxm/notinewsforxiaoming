# Web 管理台验收清单

## 验收前必须先明确的事实

### 当前验收对象

本次验收对象是 `doc/design/web-admin-console.md` 中第一阶段 Web 管理台：

- Dashboard
- Reminders
- StartGG
- resident 进程内嵌 admin API 的代码边界
- `apps/web` 独立前端工程

本次不是验收一个产品化后台，也不是验收完整 Telegram bot 替代品。

### 当前推荐的本地验收模式

本地页面验收使用 admin-only 模式。

这个模式只启动：

- admin HTTP API
- Web 静态资源服务能力
- Web API 操作所需的 Telegraf 实例

这个模式不会启动：

- Telegram long polling
- 固定时点任务
- 启动时恢复历史一次性提醒调度
- 启动时恢复历史循环提醒调度
- 维生素循环

这是为了避免本地开发和线上 resident 同时使用同一个 `TG_TOKEN` 时抢占 Telegram `getUpdates`。

### 线上 bot 不需要停

线上 resident 正在使用 Telegram long polling 时，本地不能用同一个 `TG_TOKEN` 再启动完整 resident。

如果本地完整 resident 报 Telegram `409 Conflict`，这是正常现象，不是 Web 管理台问题。原因是 Telegram Bot API 对同一个 bot token 的 long polling 只允许一个消费者。

页面验收应使用 admin-only 模式；Telegram 聊天交互主路径如需本地联调，应使用单独测试 bot token。

### 本地数据和线上数据不是同一份

Web 管理台读取的是当前本地 `data/notinews.sqlite`。

如果本地没有同步线上数据库，以下现象属于正常：

- Dashboard 统计为 0
- Reminders 表格为空
- Recurring Reminders 表格为空
- StartGG 选手、项目、快照为空
- 最近 start.gg 状态变化时间为空

这不代表页面没实现，也不代表线上数据丢失。

### StartGG 轮询状态只代表本地进程

StartGG 的固定轮询和加速轮询状态来自当前本地进程内存。

admin-only 模式不会自动继承线上 resident 的轮询状态。因此本地页面显示 polling 关闭、下一次轮询为空，可能是正常现象。

### Web 操作可能触达真实外部服务

admin-only 模式虽然不启动 Telegram long polling，但仍会读取 `.env` 并创建 Telegraf 实例。

因此以下操作可能触达真实外部服务：

- 创建未来时间的一次性提醒后，当前本地进程存活期间到点可能发送 Telegram 消息
- 创建循环提醒后，当前本地进程存活期间到点可能发送 Telegram 消息
- StartGG 的立即检查和 go 操作可能访问 start.gg，并在状态变化时发送 Telegram 消息
- polling on/off 只影响当前本地 admin 进程的 start.gg 轮询内存状态

如果只想看页面布局和数据展示，不要随意触发会访问外部服务或发送消息的操作。

### 认证不在应用内

第一阶段没有应用内登录、注册、角色、密码找回。

本地页面无需登录即可访问，这是方案预期。正式外部访问保护应放在反向代理或外层访问控制。

### 错误直接暴露是预期

本项目约束是不做兜底、不做静默跳过、不返回默认值假装成功。

因此当 `.env`、SQLite、Telegram、start.gg 等真实依赖有问题时，页面或接口直接显示错误是预期行为。验收时应把这类错误归因到对应依赖，而不是要求页面吞错后继续显示假数据。

### 第一阶段明确不包含的内容

以下内容不属于本次未完成问题：

- 多用户系统
- 应用内登录鉴权
- 复杂角色权限
- Web 版聊天机器人
- 完整替代 Telegram 命令
- 循环提醒既有规则编辑
- Web 内完整添加和切换 start.gg watch 对象
- AV 订阅管理
- 服务器巡检面板
- 投递箱 / Snippet Inbox
- 配置页

## 总体验收点

- [ ] 页面能进入 Dashboard、Reminders、StartGG 三个主页面。
- [ ] 左侧导航能在三个页面之间切换。
- [ ] 页面在桌面宽度下布局清晰，没有明显遮挡、错位、横向溢出。
- [ ] 页面在窄屏宽度下导航和主要内容能正常堆叠展示。
- [ ] 页面视觉风格一致，不出现默认脚手架页面或未替换的示例内容。
- [ ] 页面刷新后仍能回到当前 hash 路由对应页面。
- [ ] API 错误能在页面上明确提示，不静默失败。

## Dashboard 验收点

- [ ] 展示待处理一次性提醒数量。
- [ ] 展示活跃循环提醒数量。
- [ ] 展示 start.gg 监控选手数量。
- [ ] 展示 start.gg 激活项目数量。
- [ ] 展示 start.gg 固定轮询开关状态。
- [ ] 展示 start.gg 加速轮询开关状态。
- [ ] 展示下一次固定轮询时间；没有本地轮询时为空或 `-` 属于正常。
- [ ] 展示下一次加速轮询时间；没有本地加速轮询时为空或 `-` 属于正常。
- [ ] 展示最近 start.gg 状态变化时间；本地无快照时为空或 `-` 属于正常。
- [ ] 快捷入口能进入 Reminders 页面。
- [ ] 快捷入口能进入 StartGG 页面。

## Reminders 页面验收点

### 一次性提醒

- [ ] 一次性提醒 tab 存在。
- [ ] 列表展示 ID、内容、触发时间、状态、操作。
- [ ] 状态筛选支持全部、待提醒、已完成、已取消。
- [ ] 搜索框能按内容筛选。
- [ ] 新建一次性提醒弹窗包含内容和提醒时间。
- [ ] 新建成功后列表能看到新增记录。
- [ ] 编辑待提醒记录时，可以修改内容。
- [ ] 编辑待提醒记录时，可以修改提醒时间。
- [ ] 编辑成功后列表展示更新后的内容和时间。
- [ ] 待提醒记录可以标记完成。
- [ ] 标记完成后状态变为已完成。
- [ ] 待提醒记录可以取消。
- [ ] 取消后状态变为已取消。
- [ ] 已完成和已取消记录不再展示编辑、完成、取消操作。

### 循环提醒

- [ ] 循环提醒 tab 存在。
- [ ] 列表展示 ID、内容、规则文本、下次触发时间、状态、操作。
- [ ] 状态筛选支持全部、活跃、已暂停、已取消。
- [ ] 搜索框能按内容筛选。
- [ ] 新建循环提醒弹窗包含内容、频率、时间、时区。
- [ ] 每天规则可以创建。
- [ ] 每周规则可以选择星期并创建。
- [ ] 每月规则可以输入日期并创建。
- [ ] 新建成功后列表能看到新增规则。
- [ ] 活跃循环提醒可以暂停。
- [ ] 暂停后状态变为已暂停。
- [ ] 活跃循环提醒可以取消。
- [ ] 取消后状态变为已取消。
- [ ] 已暂停和已取消规则不再展示暂停、取消操作。

## StartGG 页面验收点

- [ ] 展示固定轮询状态卡。
- [ ] 展示加速轮询状态卡。
- [ ] 展示监控选手数量卡。
- [ ] 展示激活项目数量卡。
- [ ] 操作区包含立即检查。
- [ ] 操作区包含 polling on。
- [ ] 操作区包含 polling off。
- [ ] 操作区包含 go keyword 输入框。
- [ ] 操作区包含 go 操作按钮。
- [ ] 当前激活赛事列表展示赛事 / 项目、slug、更新时间。
- [ ] 当前监控选手列表展示选手名、player_id、更新时间。
- [ ] 最近状态快照表展示选手、赛事 / 项目、状态、名次、最近轮次、最近比分、快照时间。
- [ ] 本地没有 start.gg 数据时，空表格展示正常，不属于问题。
- [ ] polling on 后，本地固定轮询状态变为开。
- [ ] polling off 后，本地固定轮询状态变为关。
- [ ] start.gg 外部依赖报错时，页面展示明确错误。

## 后端边界验收点

- [ ] admin API 位于 `src/admin`。
- [ ] Web 当前使用到的 API 端点数量和方案草图一致。
- [ ] controller 只做参数解析和调用 application 层。
- [ ] reminders 主操作位于 `src/application/reminders`。
- [ ] start.gg 主操作位于 `src/application/startgg`。
- [ ] Telegram handler 不再直接复制 Web 管理台使用的提醒主路径逻辑。
- [ ] DB 中性入口位于 `src/db.ts`。
- [ ] `src/reminders/db.ts` 只保留兼容导出，不再承担实际 DB 初始化实现。
- [ ] `src/reminders/recurring.ts` 中 `rrule` 导入方式没有被修改。

## 可判定为问题的情况

- [ ] Dashboard、Reminders、StartGG 任一主页面不存在。
- [ ] 页面仍显示 Vite / Vue 默认脚手架内容。
- [ ] 左侧导航无法切换页面。
- [ ] Reminders 页面没有一次性提醒 tab。
- [ ] Reminders 页面没有循环提醒 tab。
- [ ] 一次性提醒无法新建。
- [ ] 一次性提醒无法编辑内容或时间。
- [ ] 一次性提醒无法取消或标记完成。
- [ ] 循环提醒无法新建。
- [ ] 循环提醒无法暂停或取消。
- [ ] StartGG 页面没有轮询状态区。
- [ ] StartGG 页面没有最近快照表。
- [ ] StartGG 页面没有立即检查、polling on/off、go 操作入口。
- [ ] 页面操作成功后列表或状态完全不刷新。
- [ ] API 层绕过 application 层直接散写 SQL 和 runtime 操作。

## 不应判定为问题的情况

- [ ] 本地完整 resident 使用线上同一个 `TG_TOKEN` 时出现 Telegram `409 Conflict`。
- [ ] 本地数据库没有数据导致页面统计为 0。
- [ ] 本地没有 start.gg 快照导致 StartGG 表格为空。
- [ ] admin-only 模式不恢复历史提醒调度。
- [ ] admin-only 模式不启动固定时点任务。
- [ ] admin-only 模式不接收 Telegram 聊天消息。
- [ ] 本地页面没有登录页。
- [ ] 循环提醒不能编辑既有规则。
- [ ] Web 里不能完整替代 `/watch` 的所有添加逻辑。
- [ ] AV、服务器巡检、配置页没有出现在管理台。
