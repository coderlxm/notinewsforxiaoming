## 3. 已完成的实现核对

- [x] `/note` 私有记录、`/post` 公开记录。
- [x] 命令正文、回复消息、一次性等待三条采集路径。
- [x] 一次性等待可用 `/cancel` 取消，并复用原提示消息。
- [x] 文本、图片、视频、圆形视频、动画、语音、音频、文件、贴纸及 Telegram 结构化消息映射。
- [x] 照片/视频相册聚合为一条网页记录，整组成功后才结束捕获会话。
- [x] Telegram 云端附件下载限制为单文件 20 MB，超限直接报告失败。
- [x] 原消息 `chat_id + message_id` 幂等，人工重提不会重复建立同一记录。
- [x] 公开/私有逐条切换；私有记录不进入公开详情、媒体、RSS 或 JSON Feed。
- [x] 公开单列信息流、永久详情页、标签入口和游标加载。
- [x] 私有资产搜索、标签、类型、可见性、日期筛选。
- [x] 正文编辑、置顶、往年今日。
- [x] SQLite 与媒体使用同一 `/opt/journal/data/` 持久化边界。
- [x] rndc02 不包含 `bot.launch()`、webhook 或 updates 消费路径。
- [x] Journal 故障只让 Journal 操作明确失败，不替换 Telegram 通道或改变原 bot 业务。

## 4. 需要所有者首次使用确认

以下项目必须由 Telegram 账号本人发送真实消息，交付过程没有代替所有者创建测试日记，因此保留为首用确认项：

- [ ] 发送一条 `/note` 文本，在 `/me` 中看到私有记录。
- [ ] 发送一条 `/post` 文本，在公开首页看到记录，并用结果按钮转为私有。
- [ ] 回复一条既有消息发送 `/note`，确认保存的是被回复消息。
- [ ] 单独发送 `/note`，再发送一条语音或文件，确认提示消息被编辑为保存结果。
- [ ] 发送带 `/note` caption 的照片/视频相册，确认网页只出现一条记录且媒体完整。
- [ ] 在 `/me` 中完成一次搜索、正文编辑、置顶和可见性切换。

这些项目的最短操作说明见《简易使用手册》。
