# P0-02 私人「往年今日」需求文档

> 状态：待开发  
> 目标范围：站主私有资料库 `/me`  
> 参考案例：[Day One Calendar / On This Day](https://dayoneapp.com/features/calendar-view/)

## 1. 背景

NotiNews 已经能够通过 Telegram、Web 编辑器和投稿形成长期个人档案，站主也可以在 `/me` 中搜索、筛选和管理全部记录。但当前主要浏览方式仍是从新到旧翻阅或主动输入条件，历史内容不会自然回到用户面前。

当前源码已经存在完整的查询基础：

- `GET /api/me/on-this-day`
- `JournalRepository.listOnThisDay()`
- `useJournalApi()` 中的 `onThisDayEntries`
- `OnThisDay.vue` 横向卡片组件

这些实现尚未接入当前 `FeedView` 的私有资料库主路径。现有 `loadPrivate()` 会同时请求资料库和往年今日，但当前页面实际使用的是 `refreshPrivateFeed()`，因此不能把源码中存在的组件和状态视为用户已经可用的功能。

## 2. 目标

在不改变资料库主体结构的前提下，让站主每天进入 `/me` 时都能看到历年同一天发布的记录，并能沿用现有详情、编辑和管理能力处理这些记录。

具体目标：

1. 给历史记录一个无需输入关键词的日常重访入口。
2. 复用现有 API、卡片、详情覆盖层和管理动作，不建立第二套内容页面。
3. 往年今日局部加载，不阻塞资料库列表，不造成整个页面闪现或重新初始化。
4. 在瀑布流、表格、详情打开/关闭和当日页面会话之间复用已加载状态。
5. 保证发布时间修改、内容修改、权限修改和删除后，回顾区与真实数据保持一致。

## 3. 非目标

本次不包含：

- 公开首页的历史回顾。
- Telegram 自动提醒或每日推送。
- 月历、年度热力图、年度报告。
- 随机记录、算法推荐或 AI 总结。
- 查看任意指定日期的历史内容。
- 草稿回顾。
- 修改当前 `Asia/Shanghai` 时间口径。

## 4. 使用者与核心场景

唯一使用者是已通过站主口令登录的本人。

### 场景 A：正常进入资料库

站主进入 `/me`，资料库框架与当前列表正常加载；往年今日模块在自己的区域显示局部加载状态。请求完成后，模块展示历年同月同日的记录，不影响资料库列表的可操作时间。

### 场景 B：当天没有历史记录

模块仍保留明确、紧凑的空状态，显示“今天没有往年记录”，让站主知道功能已经完成查询，而不是误以为入口消失或页面没有加载完成。

### 场景 C：从回顾打开详情

站主点击任意历史记录，进入当前私有详情覆盖层。关闭详情后回到原资料库位置，回顾横向滚动位置和资料库纵向滚动位置均保持不变。

### 场景 D：管理历史记录

站主可以沿用卡片现有动作编辑正文、文章、发布时间、可见性、频道和置顶状态，也可以删除记录。操作成功后，回顾区立即反映相同结果。

### 场景 E：切换资料库视图

站主在瀑布流与表格之间切换时，往年今日模块保持在资料库常驻框架中，不重新请求，也不因列表视图变化而丢失已加载内容。

### 场景 F：登录后进入

匿名访问者先看到现有登录界面。登录成功后，资料库列表和往年今日分别开始加载；不需要再次刷新页面。

## 5. 页面位置与信息结构

### 5.1 位置

往年今日作为 `/me` 的独立局部模块，放在资料库筛选工具栏之后、瀑布流或表格结果之前。

该位置适用于两种资料库视图：

```text
我的全部记录 / 发布内容 / 写文章 / 设置
筛选与视图工具栏
往年今日（局部模块）
当前瀑布流或表格结果
```

模块不进入公开导航，不增加新路由，也不替代“我的全部记录”标题。

### 5.2 标题

- 眉题：`往年今日`
- 主标题：`时间留下来的这一天`
- 标题语义使用二级标题，并与模块建立可访问性关联。

### 5.3 记录内容

每张卡片至少能看出：

- 原记录年份与完整日期。
- 距今年数，例如“3 年前”。
- 原频道。
- 标题或正文摘要。
- 适用的媒体预览。
- 标签。
- 当前公开状态与置顶状态。

卡片继续复用短记录和长文章的现有视觉与操作菜单，不新增一套简化数据模型。

## 6. 数据口径

### 6.1 日期定义

- “今天”按 `Asia/Shanghai` 计算。
- 使用记录的 `sourceCreatedAt` 判断其所属日期。
- 只匹配月和日相同、年份早于当前年的记录。
- 2 月 29 日只在 2 月 29 日匹配，不改写为 2 月 28 日或 3 月 1 日。

### 6.2 内容范围

包含：

- 已发布短记录。
- 已发布长文章。
- `public`、`protected`、`private` 三种可见性。
- Telegram 与 Web 两种来源。

不包含：

- 草稿。
- 当前年份的记录。
- 媒体组中的非代表记录。

### 6.3 排序

按 `sourceCreatedAt` 从近年到远年排序；同一时间使用记录 ID 从大到小保持稳定顺序。置顶状态不改变回顾区的时间顺序。

### 6.4 与资料库筛选的关系

往年今日代表独立的时间回顾，不受当前资料库的公开状态、关键词、标签、内容类型和日期筛选影响。筛选只作用于下方资料库结果。

## 7. 交互要求

### 7.1 加载

- 只有站主鉴权成功后才请求数据。
- 模块使用独立加载状态。
- 模块加载不遮挡资料库头部、工具栏或列表。
- 同一次 `/me` 页面会话中，瀑布流/表格切换和详情开关复用结果。

### 7.2 手动刷新

站主触发现有资料库刷新时，同时刷新当前列表与往年今日；两个区域分别呈现自己的进行中、成功或错误状态，一个区域的结果不覆盖另一个区域的状态。

### 7.3 打开与返回

- 点击短记录或已发布文章，打开现有私有详情覆盖层。
- 关闭详情后回到原页面，不重新创建往年今日模块。
- 通过标签进入资料库筛选时，只更新下方列表；往年今日仍保持原内容。

### 7.4 内容操作后的同步

- 修改正文、标题、标签、频道、权限或置顶后，回顾卡片立即使用服务端返回的新记录替换旧记录。
- 删除后，记录立即从回顾区移除。
- 修改发布时间后重新判断是否仍属于今天：仍属于时更新卡片，不再属于时从回顾区移除；新改成今天的其他年份时应进入回顾区。
- 编辑文章返回资料库后，若文章内容发生变化，回顾区显示更新后的服务端数据。

## 8. 状态与反馈

| 状态 | 页面表现 |
| --- | --- |
| 未登录 | 不展示模块，也不发起请求 |
| 加载中 | 只在模块位置显示回顾加载状态 |
| 有结果 | 横向展示记录卡片 |
| 无结果 | 显示“今天没有往年记录” |
| 请求失败 | 在模块内展示真实错误信息，不把模块伪装成空结果 |
| 登录失效 | 进入现有匿名鉴权状态，停止展示私人内容 |
| 单条内容操作中 | 只禁用对应卡片的冲突操作并显示现有操作反馈 |

不增加自动重试、静默跳过或默认数据。

## 9. 响应式与可访问性

- 桌面端与移动端均使用横向卡片轨道，不能挤压下方资料库主结果。
- 横向区域可通过触控板、触屏和键盘滚动。
- 模块标题、加载状态和空状态可以被辅助技术识别。
- 卡片中已有按钮保持其原语义和焦点顺序。
- 遵循系统减少动态效果偏好，不新增连续动画。

## 10. 完成标准

1. 已登录站主首次进入 `/me` 时能看到独立的往年今日加载及结果区域。
2. 瀑布流和表格均共享同一回顾模块，切换视图不重新加载已有结果。
3. 查询严格遵循上海日期、历史年份、已发布记录和媒体组代表项规则。
4. 三种可见性只在站主已登录环境中展示。
5. 有结果、无结果、加载失败和登录失效均有明确且互不混淆的页面状态。
6. 从回顾打开并关闭详情后，资料库和回顾位置保持。
7. 正文、权限、频道、置顶、发布时间和删除操作后，回顾内容与服务端结果一致。
8. 功能没有新增公开 API、公开导航、推送、日历或推荐能力。

## 11. 依赖与后续关系

- 直接依赖当前站主鉴权、`/api/me/on-this-day`、`JournalEntry`、现有卡片和私有详情覆盖层。
- 不依赖公开搜索、详情页继续探索或数据导出，可以独立开发。
- 后续如开发月历、随机漫游或 Telegram 周报，应复用这里确立的上海日期与私人权限口径，而不是改变本 P0 的日常入口。
