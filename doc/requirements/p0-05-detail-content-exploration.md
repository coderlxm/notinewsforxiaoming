# P0-05 详情页「继续探索」需求文档

> 状态：待开发  
> 目标范围：公开短记录与长文章详情  
> 参考案例：[Quartz Backlinks](https://quartz.jzhao.xyz/features/backlinks)、[Are.na Connections](https://help.are.na/docs/getting-started/connections)

## 1. 背景

NotiNews 的公开 feed 已经可以按频道和标签浏览，短记录与长文章也有完整详情。但用户读完一条内容后，当前页面基本结束：标签可以返回频道过滤，却没有沿时间继续阅读或直接看到与当前内容共享主题的记录。

本功能不建立推荐算法，而是把项目已经拥有的两个确定关系变成阅读入口：

- `sourceCreatedAt` 形成的时间相邻关系。
- 人工或 AI 已确认标签形成的共同主题关系。

## 2. 目标

1. 在每个可阅读的公开详情底部提供更早、较新和相关内容入口。
2. 关系必须可解释，用户能知道内容为什么被关联。
3. 继续复用现有永久链接、详情展示、口令解锁和 feed 状态保持机制。
4. 从信息流打开、直接访问永久链接、连续打开相关内容和浏览器返回时，导航行为一致。
5. 严格保护私有和未解锁口令内容，不通过相关关系泄露标题、正文、标签或媒体。

## 3. 非目标

本次不包含：

- AI 语义推荐、向量搜索或用户画像。
- 点击率、点赞、热度或协同过滤。
- 手动建立关系、反向链接或知识图谱。
- 私有资料库中的相关内容模块。
- 草稿之间的关系。
- 专题集合、照片合集或保存视图。
- 无限推荐流。

## 4. 术语

- **较新一条**：按 `sourceCreatedAt` 和 ID 排序，时间上紧邻当前内容且更晚的一条公开内容。
- **较早一条**：按相同顺序，时间上紧邻当前内容且更早的一条公开内容。
- **相关记录**：与当前内容至少共享一个完全相同标签的公开内容。
- **当前内容**：用户正在阅读的已发布公开内容，或已经通过口令解锁的已发布受保护内容。

“较新/较早”不使用“上一篇/下一篇”，避免不同排序方向造成理解歧义。置顶仅影响 feed 展示，不改变时间相邻关系。

## 5. 用户场景

### 场景 A：从信息流打开短记录

用户在瀑布流中打开一条短记录，详情覆盖层底部局部加载继续探索。点击一条候选内容后，在同一个详情层打开目标内容；关闭后仍回到原信息流及原滚动位置。

### 场景 B：直接打开永久链接

用户直接进入 `/p/:publicId`，读完后打开较早、较新或相关内容。URL 更新为目标永久链接，浏览器返回可回到刚才的详情，再返回对应频道。

### 场景 C：阅读长文章

长文章正文和标签之后显示继续探索，不干扰目录与正文锚点。候选内容可以是短记录，也可以是文章。

### 场景 D：阅读口令内容

未解锁时只显示当前口令输入界面，不请求或展示继续探索。解锁成功后才加载；候选内容只包含普通公开内容。

### 场景 E：没有候选内容

没有较新或较早内容时不显示对应方向；没有共同标签内容时不显示“相关记录”区域。页面不生成随机替代内容。

### 场景 F：局部请求失败

当前详情仍正常显示，继续探索区域明确显示真实错误信息；错误不能伪装成“没有相关内容”，也不自动再次请求。

## 6. 关系规则

### 6.1 候选内容共同条件

所有候选内容必须：

- `publicationStatus = published`。
- `visibility = public`。
- 是媒体组代表记录。
- 不等于当前内容。

候选池不包含口令内容，即使当前浏览器曾解锁其他口令记录，也不通过继续探索主动暴露它们。私有内容与草稿始终排除。

### 6.2 时间相邻

- 使用 `sourceCreatedAt` 排序，时间相同则使用 ID 排序。
- 较新一条与较早一条各最多一条。
- 不使用置顶状态。
- 不限定当前频道或内容类型。

### 6.3 相关记录

- 当前内容至少有一个标签时才查询。
- 候选必须与当前内容共享至少一个完全相同的标签。
- 最多返回三条。
- 排序依次为：共同标签数量更多、与当前内容时间距离更近、来源时间更新、ID 更大。
- 已作为较新或较早入口出现的记录从相关记录中排除，避免同一详情重复出现。
- 每条结果展示共同标签，让关联理由可见。
- 不使用频道相同或时间接近生成无标签关系。

## 7. 展示设计

### 7.1 位置

模块位于正文、媒体、结构化内容和当前标签之后，是详情内容的最后一个阅读区块。

长文章目录仍只跟踪正文 H2/H3，不把“继续探索”加入目录。

### 7.2 区块结构

```text
继续探索
┌ 较新一条 ───────────┐  ┌ 较早一条 ───────────┐
│ 日期 / 类型 / 摘要  │  │ 日期 / 类型 / 摘要  │
└────────────────────┘  └────────────────────┘

相关记录
· 标题或正文摘要 · 日期 · 共同标签
· ...
```

窄屏按单列排列，桌面端时间相邻入口可以双列。模块采用紧凑摘要，不重复渲染完整正文或完整媒体画廊。

### 7.3 候选摘要

每项至少包含：

- 关系标签：较新一条、较早一条或相关记录。
- 内容类型：记录或文章。
- 标题；没有标题时使用截断后的纯文本摘要。
- 来源日期。
- 频道。
- 相关记录的共同标签。
- 可用时显示首张预览图或文章封面，但不因此改变卡片高度主结构。

## 8. 加载与导航

### 8.1 加载时机

- 当前公开详情数据可用后，模块独立发起请求。
- 口令内容只有解锁并取得完整 `JournalEntry` 后才发起。
- 私有详情和文章编辑预览不发起。
- 切换到另一条详情时，目标内容使用自己的新组件实例加载，不通过监听旧 props 驱动。

### 8.2 页面状态

| 状态 | 表现 |
| --- | --- |
| 加载中 | 详情底部显示局部加载提示 |
| 有相邻/相关结果 | 只显示存在的区块和方向 |
| 全部为空 | 不显示整个继续探索模块 |
| 请求失败 | 显示明确错误区域 |
| 当前内容 404 | 沿用详情页现有 404，不请求继续探索 |
| 口令未解锁 | 不显示、不请求 |

### 8.3 打开候选内容

- 从信息流详情覆盖层打开时，继续使用当前详情层和底层 feed 上下文。
- 从直接永久链接打开时，以新永久链接替换当前阅读内容，并把一次导航写入浏览器历史。
- 浏览器返回按访问顺序返回上一条详情。
- 返回原 feed 后，已加载列表和滚动位置保持。
- 不打开新窗口，不创建叠加的第二层弹窗。

## 9. 权限与隐私

1. 私有内容无法作为当前公开详情，也不产生继续探索响应。
2. 未解锁口令内容请求继续探索时，与读取该详情一致地要求当前口令授权。
3. 口令内容解锁后可以使用其真实标签计算关系，但响应候选仍然只包含普通公开内容。
4. API 不返回未解锁口令候选的标题、正文、标签、媒体或关系原因。
5. 站主 cookie 可以读取当前口令内容，但不会改变候选池只包含 `public` 的规则。

## 10. 完成标准

1. 公开短记录和长文章详情均能显示较新、较早和共同标签相关内容。
2. 时间关系严格按来源时间和 ID 计算，不受置顶、频道和内容类型影响。
3. 相关结果必须共享标签、显示共同标签，最多三条且不与时间相邻项重复。
4. 私有、草稿和口令候选不会出现；当前口令内容在解锁前不发请求。
5. 信息流覆盖层、直接永久链接、连续详情导航和浏览器返回均沿用现有页面上下文。
6. 模块加载与错误是局部状态，不遮挡当前详情；失败真实暴露且不自动请求。
7. 没有结果时不生成随机、同频道或热门内容作为替代。
8. 文章编辑预览和私有详情不出现该模块。

## 11. 后续关系

本 P0 建立的是只读、可解释的自动关系。后续可以基于真实使用独立增加：

- 手动“后续/来源/同一事件”关系。
- 反向引用。
- 专题集合。
- 私人详情中的跨可见性关联。

这些能力不得预先塞入本次接口或页面状态。
