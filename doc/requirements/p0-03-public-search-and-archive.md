# P0-03 公开搜索与年月归档需求文档

> 功能编号：P0-03  
> 当前阶段：待开发  
> 文档日期：2026-08-12  
> 上游依据：`doc/research/notinews-web-feature-benchmark-and-p0.md`

## 1. 背景与现状

NotiNews 的公开端已经支持“生活、文章、兴趣”三个频道、频道公开标签、无限加载和永久详情页，但旧内容只能沿时间线下翻，或者依赖站主预先配置的少量标签进入。内容数量增长后，访问者缺少两条基本找回路径：

- 知道内容大意时，无法按标题、正文或标签检索。
- 记得大致时间时，无法按年份和月份回看。

当前源码中，与本需求直接相关的事实是：

- `/` 通过 `channel`、`tag` 查询参数表达公开 feed 状态。
- `/p/:publicId` 是公开记录和文章共用的永久详情地址。
- 私有资料库已经支持标题、正文关键词、标签、类型和时间范围筛选，但它是站主接口，不能直接用于公开端。
- 公开 feed 会展示已发布的 `public` 内容，以及未解锁 `protected` 内容的脱敏预览；脱敏预览只有永久 ID、频道、记录/文章类型和来源时间。
- `App.vue` 已经保存公开 feed 的已加载状态与滚动位置，详情返回时会复用原 feed。
- 当前没有 `/search`、`/archive` 公开路由，也没有公开搜索或年月聚合接口。

以上属于当前源码行为。本需求中的页面结构、查询语义和优先级属于本次产品决定。

## 2. 要解决的问题

1. 访问者无法通过自己记得的关键词找到一条公开记录或文章。
2. 中文短语、多个关键词和标签缺少一致、可理解的查询语义。
3. 访问者无法快速判断某年某月有哪些内容。
4. 搜索或归档进入详情后，如果返回时结果重新加载、位置回到顶部，会破坏连续浏览。
5. 公开搜索如果错误复用私有查询，可能通过命中、摘要或标签泄露口令内容和私有内容。

## 3. 目标

### 3.1 用户目标

- 从任一公开信息流快速进入搜索，并可用键盘快捷键直达。
- 通过中文或英文关键词查找已发布且当前有权阅读的内容。
- 通过年、月浏览公开端可到达的历史内容。
- 搜索词和归档月份都由 URL 明确表达，可以复制、刷新、前进和后退。
- 从结果进入永久详情，再返回原查询、原结果和原滚动位置。

### 3.2 产品目标

- 让已发布内容在时间线之外具备稳定的站内发现入口。
- 复用现有内容字段、权限模型、详情路径和页面常驻框架。
- 为后续相关内容、专题集合等能力建立统一的公开内容摘要语义。

## 4. 非目标

本次不包含：

- 私有资料库搜索改造。
- 语义搜索、向量搜索、拼音搜索、同义词扩展或聊天式问答。
- 搜索联想、热门词、搜索历史和可保存的复杂查询表达式。
- 按日历日、地点、媒体类型或自定义日期范围浏览公开归档。
- 为归档增加专题、相册或年度总结。
- 让未解锁的口令内容参与关键词命中。
- 把草稿或私有内容混入任何公开搜索、数量或归档列表。

## 5. 用户与核心场景

### 5.1 普通访问者

- “我记得小明写过上海旅行，想直接搜到那条内容。”
- “我想看看 2025 年 10 月发布过什么。”
- “我从搜索结果打开一条记录，看完后希望回到原位置继续浏览。”

### 5.2 已解锁口令内容的访问者

- “我已经输入过某条口令，希望这条有权阅读的内容能正常参与当前会话的搜索和归档展示。”

### 5.3 已登录站主

- 站主使用公开搜索时，只查看公开端可到达的已发布内容；私有记录和草稿仍然只在 `/me` 中检索。
- 站主身份可以阅读全部已发布口令内容，因此这些内容可在站主的公开搜索结果中出现。

## 6. 信息架构与地址

### 6.1 入口

- 公开阅读面的 Header 中间常驻一条完整搜索栏，作为公开内容搜索的唯一主入口。公开信息流、关于页、搜索页、归档页和公开详情均显示该搜索栏。
- 搜索栏不是只带图标的跳转按钮：访客可以直接输入关键词，按 Enter 或点击末端搜索按钮后进入搜索结果页。
- 搜索结果页不再重复放置第二个大型搜索框；Header 搜索栏始终是修改关键词和再次提交的主要位置。
- “归档”仍作为公开信息流标题区的次级入口，并在搜索结果区域提供文字入口；它不与搜索栏争夺 Header 主视觉。
- 不改变现有四项移动端频道导航结构，不把搜索和归档硬塞成新的频道。

### 6.2 Header 搜索栏视觉与布局

搜索栏借鉴用户指定的小红书 Web 首页截图所体现的布局关系：品牌/身份在左、搜索居中、账户或管理入口在右。只借鉴信息层级与比例，不复制其品牌颜色、图标或文案。

宽屏 Header 结构为：

```text
头像、名称与简介      居中的长圆角搜索栏      站主管理入口（如有）
```

具体要求：

- 搜索栏在可用空间中视觉居中，宽度明显大于普通按钮，但设置合理最大宽度，不能挤压站点身份和站主管理入口。
- 使用长圆角容器、当前主题的弱对比表面色和细边界；聚焦时使用站点已有强调色表达焦点，不照搬小红书红色。
- 占位文案为“搜索公开记录和文章”，搜索图标位于输入框末端并同时作为提交按钮。
- 输入文字、占位文字、清除控件和搜索按钮均适配现有明暗主题。
- 中等宽度和移动端改为两行：第一行保留紧凑站点身份及适用的站主管理入口，第二行由搜索栏占满可用宽度。
- 搜索栏属于现有可收起的 `profile-bar`，继续沿用当前向下滚动收起、向上滚动显示的 Header 行为，不另外增加悬浮层或第二个固定顶栏。
- 公开详情覆盖层出现时，底层 Header 搜索栏保持原位置；弹层的焦点管理优先，快捷键不得把焦点从已打开的对话框中抢走。

### 6.3 页面地址

| 页面 | 地址 | URL 表达的状态 |
| --- | --- | --- |
| 搜索起始页 | `/search` | 尚未提交关键词 |
| 搜索结果页 | `/search?q=上海%20旅行` | 规范化后的查询词 |
| 归档总览 | `/archive` | 全部年份和月份 |
| 月份归档 | `/archive/2025/10` | 2025 年 10 月 |

约束：

- `q` 只允许一个字符串值；重复参数、数组值或超过长度限制的值不作为有效搜索状态。
- 归档年份使用四位数字，月份使用 `01` 至 `12` 两位数字。
- 分页游标属于当前已加载页面状态，不进入公开 URL。
- 不在 URL 中保存滚动像素；滚动位置由应用现有页面状态机制复用。

### 6.4 与 P0-01 页面发现能力的关系

- `/search` 和带 `q` 的搜索结果页使用 `noindex, follow`，Canonical 统一为 `/search`，不进入 sitemap，避免任意用户查询形成可索引页面集合。
- `/archive` 使用自己的 Canonical、`index, follow` 和 `CollectionPage` 元数据。
- `/archive/:year/:month` 使用自己的 Canonical、`index, follow` 和对应年月的 `CollectionPage` 元数据。
- P0-03 落地时，把 `/archive` 和当前有内容的年月归档 URL 加入 P0-01 的 sitemap；口令、私有和草稿仍不因此进入 sitemap。
- 若 P0-01 已先完成，P0-03 必须扩展同一个服务端页面文档与客户端 head 所有者，不重新引入静态 `sendApplication` 或第二套标题逻辑。

## 7. 搜索需求

### 7.1 搜索入口与快捷键

- 点击 Header 搜索栏直接进入输入状态，不立即改变当前路由；提交有效关键词后才进入 `/search?q=...`。
- 在公开信息流、关于页、搜索页、归档页和公开详情按 `Cmd + K`（macOS）或 `Ctrl + K`（Windows/Linux），聚焦 Header 搜索栏。
- 已在搜索结果页时使用快捷键，应聚焦并选中当前查询词，不重复导航。
- 快捷键只在公开阅读表面生效，不劫持 `/me`、编辑器、设置和投稿管理中的按键。
- 当前存在打开的详情 `<dialog>` 或焦点正处于其他可编辑控件时，快捷键不抢夺焦点。
- 只有快捷键被本功能实际处理时才阻止浏览器默认行为。
- 直接打开带查询词的 URL 时直接显示结果，不强制弹出移动端软键盘。

### 7.2 输入与提交

- 搜索框使用 `type="search"`，提供明确的“搜索”提交按钮。
- 用户按 Enter 或点击按钮后提交；输入过程中不自动请求。
- 中文输入法组合状态尚未结束时不得提交半成品文本。
- 提交时执行以下规范化：去除首尾空白，把连续空白合并为一个空格。
- 规范化后为空时进入 `/search` 起始状态，不发起查询。
- 查询词最长 80 个字符。
- 提交新查询使用新的浏览历史记录；浏览器后退可回到前一个查询或来源页面。
- 进入搜索结果页后，Header 搜索栏显示 URL 中的规范化查询词；离开搜索页后恢复为空输入和占位文案。浏览器返回搜索页时再由 URL 恢复查询词。

### 7.3 查询语义

- 搜索字段为标题、正文纯文本和标签。
- 以空白分隔多个关键词，所有关键词都必须在上述任一字段中找到；不同关键词可以命中不同字段。
- 连续中文不做手写分词，按原字符子串匹配。例如“上海旅行”命中包含连续“上海旅行”的标题、正文或标签。
- `上海 旅行` 表示同时包含“上海”和“旅行”，不要求两者连续。
- `%`、`_`、引号、减号和布尔单词均作为普通字符，不解释为通配符或查询运算符。
- ASCII 英文字母不区分大小写；本期不承诺非 ASCII 字母的大小写归一、简繁转换或拼音命中。
- 富文本文章使用当前保存的正文纯文本参与搜索，不直接搜索富文本 JSON。

### 7.4 结果排序

结果顺序必须稳定且可解释：

1. 完整查询短语命中标题。
2. 完整查询短语精确命中某个标签。
3. 完整查询短语命中正文。
4. 仅由拆分关键词共同命中的其他结果。
5. 同一优先级内按来源时间倒序，再按内部记录 ID 倒序。

置顶状态不影响搜索排序；置顶只属于频道 feed 的展示规则。

### 7.5 搜索结果字段与呈现

每条可阅读结果展示：

- 标题；无标题的短记录不虚构标题。
- 正文摘要，最多约 120 个可见字符；正文命中时围绕首个命中位置截取，否则取正文开头。
- 来源日期，按 `Asia/Shanghai` 显示。
- 频道名称。
- 内容类型，并区分“记录”和“文章”。
- 标签。
- 口令内容在已经授权时显示加密标识。

查询词在标题、摘要和标签中高亮。高亮只改变视觉强调，不拼接或解析结果 HTML，也不改变屏幕阅读器读到的原始文字顺序。

结果列表采用紧凑的单列结构，不复用瀑布流，不加载媒体原图、视频或完整富文本。每页 20 条，继续向下时按同一排序加载下一页。

### 7.6 结果点击

- 点击结果统一进入既有 `/p/:publicId` 永久详情。
- 短记录和文章都复用当前直接详情页，不为搜索建立第二套详情组件。
- 详情内点击标签仍沿现有频道标签路径处理，不把标签点击强制改为全文搜索。

## 8. 年月归档需求

### 8.1 归档总览

- `/archive` 按年份倒序展示，年份内按月份倒序展示。
- 每个月显示该月在公开端可到达的已发布内容数量。
- 没有内容的月份不生成占位格。
- 数量以一组 Telegram 媒体消息的代表记录为一条，和当前公开 feed 的记录口径一致。
- 年月归属统一按 `Asia/Shanghai` 计算，以 `sourceCreatedAt` 为准，不使用采集时间或更新时间。

### 8.2 月份页面

- 点击月份进入 `/archive/:year/:month`。
- 页面保留年份和月份上下文，并提供回到归档总览的明确入口。
- 内容按来源时间倒序、内部记录 ID 倒序排列，置顶状态不改变归档时间顺序。
- 每条普通内容展示日期、标题或正文摘要、频道、内容类型和标签。
- 每页 20 条，使用游标继续加载更早内容。
- 月份 URL 对应的内容后来被移除时，页面显示该月没有公开内容，不跳转到其他月份。

### 8.3 口令内容在归档中的表现

- 未解锁的已发布口令内容计入归档月份数量，因为它本来就在公开 feed 中以受限预览存在。
- 未解锁时，月份列表只显示既有受限预览允许的字段：日期、频道、“加密记录/加密文章”和解锁动作。
- 未解锁项不得显示或派生标题、摘要、标签、媒体缩略图和内容类型细节。
- 点击受限预览进入既有口令详情与解锁流程。
- 已解锁或站主可读时，按普通可阅读内容展示，并保留加密标识。

## 9. 权限与数据边界

| 内容状态 | 关键词搜索 | 归档数量 | 月份列表 | 详情 |
| --- | --- | --- | --- | --- |
| 已发布 `public` | 可命中并展示完整摘要 | 计入 | 展示普通条目 | 既有公开详情 |
| 已发布 `protected`，未解锁 | 完全排除，不返回“有一条命中”的迹象 | 计入 | 仅受限预览 | 既有解锁页 |
| 已发布 `protected`，当前请求已授权 | 可命中并展示可读摘要 | 计入 | 展示普通条目并标记加密 | 既有可读详情 |
| 已发布 `protected`，站主已登录 | 可命中并展示可读摘要 | 计入 | 展示普通条目并标记加密 | 既有可读详情 |
| `private` | 排除 | 不计入 | 不返回 | 公开地址仍不可访问 |
| `draft` | 排除 | 不计入 | 不返回 | 公开地址仍不可访问 |

搜索结果会随站主会话和已签名的口令授权 Cookie 变化。服务端必须先确定当前可搜索的记录集合，再执行内容命中；不能先用口令正文命中后再把结果替换成脱敏卡片。

## 10. 页面状态

### 10.1 搜索页

| 状态 | 呈现 |
| --- | --- |
| 无查询词 | Header 搜索栏常驻，结果区域提示“输入标题、正文或标签开始搜索”，并提供归档入口 |
| 首次加载 | 页面框架和 Header 搜索栏常驻，只在结果区域显示加载状态 |
| 有结果 | 显示结果列表和继续加载状态 |
| 无结果 | 显示“没有找到与‘查询词’相关的公开内容”，保留原查询词 |
| 首次请求错误 | 在结果区域直接展示真实错误，搜索框保持可操作，不展示虚构结果 |
| 后续分页错误 | 保留已经成功加载的结果，在列表尾部展示真实错误，不把错误表现成“已经全部加载” |

### 10.2 归档页

| 状态 | 呈现 |
| --- | --- |
| 总览加载 | 归档标题和 Header 搜索栏常驻，只在年月区域显示加载状态 |
| 总览为空 | 显示“还没有可以归档的公开内容” |
| 月份加载 | 年月标题和返回入口常驻，只替换列表区域 |
| 月份为空 | 显示“这个月份没有公开内容” |
| 请求错误 | 在对应局部区域直接展示真实错误，不自动请求、不跳到其他月份、不用旧数据假装成功 |

## 11. 返回、缓存与滚动

- 搜索结果和月份归档属于可复用的公开列表状态。
- 每个规范化搜索 URL、归档总览和月份 URL 使用各自的页面状态；最近 30 个发现页状态按现有公开 feed 的有上限缓存方式复用，避免无界增长。
- 站主与普通访客的发现页缓存彼此隔离；新解锁口令内容后，搜索结果按新的授权范围重新读取，归档列表则把对应受限预览更新为已解锁内容。
- 打开详情时不清空查询结果、分页游标、已加载条目和归档总览。
- 从详情返回时恢复进入详情前的 URL、结果内容和滚动位置，不重新跳到列表顶部。
- 从直接分享的详情地址进入、且浏览器没有搜索或归档来源历史时，沿现有详情返回规则回到内容所属频道。
- 切换为新的查询词或新的归档月份时，新列表从顶部开始；浏览器回到之前的 URL 时恢复该 URL 已记录的滚动位置。
- 搜索和归档请求只更新内容区域，不引起头像、简介、公开频道导航等站点框架闪现或重载。

## 12. 可访问性与响应式要求

- 搜索框有可见标签或等价的无障碍名称。
- 搜索提交、搜索入口、归档月份和结果条目都可通过键盘操作。
- 当前搜索页、归档页和月份应通过标题或 `aria-current` 清楚表达，不假装属于某个频道。
- 加载区域使用 `aria-busy` 或现有加载组件表达状态。
- 结果中的高亮不能只依赖颜色区分。
- 移动端 Header 搜索栏独占第二行，结果维持单列；它不挤压现有四项频道导航，也不与站点名称并排压缩成不可用的短输入框。
- 不为本功能引入依赖连续动画的交互。

## 13. 完成标准

### 13.1 搜索

- 公开阅读面 Header 中存在居中的长圆角搜索栏；宽屏、窄屏、明暗主题及 Header 收起行为符合第 6.2 节，公开阅读面的 `Cmd/Ctrl + K` 行为符合本需求。
- `/search?q=上海`、`/search?q=上海%20旅行` 等地址可以直接打开并得到一致查询语义。
- 中文连续子串、空格分隔多关键词、ASCII 大小写和普通通配符字符按第 7.3 节执行。
- 结果字段、排序、高亮、20 条游标分页和空状态符合本需求。
- 未授权口令内容不会通过命中结果、标题、摘要、标签或结果数量暴露；私有和草稿内容始终不进入公开搜索。

### 13.2 归档

- `/archive` 能按上海时区展示真实年份、月份与数量。
- `/archive/:year/:month` 能直接打开并按时间倒序浏览对应月份。
- 普通、未解锁口令、已解锁口令、私有和草稿内容分别遵守第 9 节边界。
- 媒体组只计数和展示一次。

### 13.3 连续体验

- 搜索或归档进入短记录、文章、口令解锁页后，返回时保留原 URL、已加载状态和滚动位置。
- 页面加载、空结果和错误都只影响局部结果区域，站点框架保持常驻。
- 错误被直接展示，不存在自动重试、替代查询、静默跳过或默认结果。
