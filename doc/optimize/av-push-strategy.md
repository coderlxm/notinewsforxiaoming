# AV 推送策略优化方案（按订阅类型隔离）

## 背景与问题

当前 `/fetchav` 统一使用“每目标只取最新 1 条”的策略。  
这对 `star`（演员）基本合理，但对 `label`（片商，如 Madonna）会漏掉同批次更新数据。

已识别问题：

1. 片商常见“同日批量更新”，只推 1 条会浪费已拉取数据。
2. 演员与片商更新节奏差异明显，应分开消息策略，避免信息流污染。

## 目标

1. 保留演员订阅当前体验（高质量单条卡片）。
2. 片商订阅支持“批量感知 + 有节制推送”。
3. 为后续更多订阅类型预留扩展位，避免再改主流程。

## 核心设计

### 1) 按类型分流处理

在 AV 拉取主流程中按 `target_type` 分发：

- `star`：继续沿用当前单条“详情卡片 + 组图”策略。
- `label`：切换为“摘要消息 + 可选少量详情”的批量策略。

建议新增处理器结构（不改业务语义）：

- `processStarTarget(target, items)`
- `processLabelTarget(target, items)`

### 2) 片商推送策略（重点）

片商目标不再只看 1 条，改为：

1. 每次拉取最近 `N` 条（建议 `N=10`，后续可配置）。
2. 用 `push_history(target_id, item_guid)` 去重，筛出“未推送新条目”。
3. 对新条目按“发行日期（或 pubDate）分组”，优先关注“当天/最新日期批次”。
4. 输出一条摘要消息（默认 1 条），内容包含：
   - 片商名
   - 本次新增总数
   - 最新更新日期
   - 前 `K` 个作品简表（建议 `K=3`，超出显示“还有 X 条”）
5. 可选：仅对第一条作品补发 1 条详情卡片（不发整组图），控制噪音。

这样能兼顾“我知道有一批更新”与“不刷屏”。

补充约束（本次新增）：

1. **增量摘要 + TopK 固化**  
   - 拉取窗口固定为最近 `N=10` 条。  
   - 推送固定为 1 条摘要消息。  
   - 摘要仅展示前 `K=3` 条，剩余用“还有 X 条”表示。  
   - 禁止把窗口内所有条目逐条推送。

2. **按日期批次聚合**  
   - `label` 目标按 `releaseDate/pubDate` 分组。  
   - 同一日期内的新条目视为一个批次。  
   - 摘要以“最新日期批次”为主输出，避免跨日期混杂。

3. **摘要级去重键**  
   - 在现有 `item_guid` 去重外，增加批次级去重。  
   - 建议去重键：`source + target_type + target_id + batch_date`。  
   - 目标：同一片商同一日期批次不重复发摘要。

### 3) 演员推送策略（保持）

`star` 维持当前策略：

- 每次看最新 1 条（或可扩展为 2 条）
- 使用现有详情模板（标题/翻译/磁力/组图）
- 与现有去重一致

### 4) 消息模板隔离

建议明确两套 formatter：

- `formatAvStarUpdateMessage(...)`
- `formatAvLabelBatchSummaryMessage(...)`

片商摘要示例（方向）：

```text
🏢 片商更新：Madonna
最新更新日期：2026-05-15
本次新增：6 部

1) ABC-123 演员A
2) DEF-456 演员B
3) GHI-789 演员C
… 还有 3 部
```

## 数据与存储建议

当前 `push_history` 设计可复用，不需要新增复杂状态机。  
只需确保片商模式下会把本次摘要中涉及的全部 `item_guid` 标记为已推送，避免重复汇总。

可选增强（后续）：

- 增加 `push_mode` 字段（`star_detail` / `label_batch`），用于审计消息策略效果。
- 增加 `batch_dedupe_key` 字段，记录摘要级去重命中情况。

## 执行流程（建议）

1. 拉取目标列表。
2. 并行处理目标（已具备）。
3. 对每个目标按 `target_type` 走对应处理器。
4. 汇总 `pushed/skipped`，返回给 `/fetchav` 与定时任务。

## 配置建议

新增可配置项（环境变量或常量）：

- `AV_LABEL_FETCH_LIMIT=10`
- `AV_LABEL_SUMMARY_TOPK=3`
- `AV_LABEL_SEND_DETAIL=false`
- `AV_LABEL_BATCH_DEDUPE=true`

## 风险与控制

1. 片商批量过大：
   - 通过 `N` 和 `K` 限流。
2. 仍可能刷屏：
   - 默认仅 1 条摘要，不逐条发送。
3. 与现有逻辑耦合：
   - 用类型处理器隔离，避免把 `star` 逻辑污染成条件分支堆叠。

## 验收标准

1. `star` 订阅：行为与当前一致，仍可收到详情+组图。
2. `label` 订阅：当同日有多条更新时，至少收到 1 条批量摘要，且包含“总数+前K条+剩余数”。
3. 连续两次 `/fetchav force`：
   - 强制模式可重复推送用于验收；
   - 普通模式不重复推送已记录条目。
4. 助手信息流不出现“同批次多条刷屏”。
