# AV RSS 数据可挖掘功能建议

## 目标

这份文档只关注一件事：JavBus RSS 已经拉到了哪些真实内容，但当前 AV 推送还没有充分用起来。

不是优化速度，不是做观测工具，而是提升用户真正关心的内容价值：

- 这部片值不值得看
- 适不适合我的口味
- 下哪个版本
- 有没有同系列/同制作商可追
- 片商批量更新里哪些值得点开

## 当前 RSS 已有数据

从线上样本和 `doc/bug/2026-05-12_av_rss_raw_sample_star_vwq.json` 可见，单条 RSS item 里实际有：

- 标题：`title`
- 详情页：`link`
- 发布时间：`pubDate` / `isoDate`
- 识别码：如 `JUR-704`
- 发行日期：如 `2026-05-07`
- 时长：如 `141分鐘`
- 导演：如 `三島六三郎`
- 制作商：如 `マドンナ`
- 发行商：如 `Madonna`
- 系列：如 `学級委員の僕だけが知る生徒指導・○○先生の裏の顔。`
- 类别标签：如 `女教師`、`羞恥`、`已婚婦女`、`成熟的女人`、`巨尻`、`單體作品`、`DMM獨家`、`高畫質`
- 演员：RSS `author` / HTML 演员区
- 封面图：`a.bigImage href`
- 样品图：`樣品圖像` 下多张 `img`
- 磁力列表：多版本 magnet、文件名、大小、分享日期
- RSS categories：类别 + 演员名

当前代码已经解析了其中一部分：

- `parseAvContent` 已解析：识别码、发行日期、时长、导演、制作商、发行商、系列、类别、封面、样品图、磁力。
- `formatAvUpdateMessage` 当前只展示：演员、识别码、标题、制作商、类别、最优磁力、详情链接。

也就是说，很多已经到手的数据没有被转化成用户决策信息。

## 建议一：新增“口味命中卡”

### 问题

用户看 AV 更新，最关心的不是完整元数据，而是这部是否命中口味。

RSS 已有类别标签，但现在只是平铺展示：

```text
#女教師 #羞恥 #已婚婦女 #成熟的女人 #巨尻 #單體作品 #DMM獨家 #高畫質
```

这能看，但还不够直接。

### 建议

把类别标签按用户决策维度分组，做成“口味命中卡”：

```text
🎯 口味命中
场景：女教师 / 校内 / 已婚
风格：羞耻 / 成熟
身材：巨尻
规格：单体 / DMM独家 / 高画质
```

可以先不用 AI，直接做小型映射表：

- 场景：女教師、学校、痴漢、人妻、已婚婦女
- 身材：巨乳、巨尻、美脚、スレンダー
- 风格：羞恥、凌辱、癒し、誘惑、寝取られ
- 规格：高畫質、DMM獨家、單體作品

### 价值

- 用户不用在一串标签里自己判断。
- 推送从“信息罗列”变成“是否合口味”的判断辅助。
- 不依赖额外数据源，直接消费 RSS 已有标签。

## 建议二：新增“作品档案字段”：发行日、时长、导演、发行商、系列

### 问题

当前 formatter 没展示：

- 发行日期
- 时长
- 导演
- 发行商
- 系列

这些字段已被 `parseAvContent` 解析，但推送里没用。

### 建议

在 star 详情卡片里增加一段短档案：

```text
📄 作品档案
发行：2026-05-07
时长：141 分钟
发行商：Madonna
系列：学級委員の僕だけが知る...
导演：三島六三郎
```

字段展示规则保持短：

- 有值才展示。
- 系列名太长时截断。
- 导演优先级低，可放最后。

### 价值

- 发行日期能判断是否真新作。
- 时长能判断片长是否合适。
- 系列是很强的口味线索。
- 发行商和制作商能辅助判断质量稳定性。

## 建议三：新增“同系列追踪建议”

### 问题

RSS 里有 `series` 字段，但当前只展示单部作品。

对用户来说，如果某个系列命中口味，后续同系列作品很可能也值得关注。

样本里：

```text
系列：学級委員の僕だけが知る生徒指導・○○先生の裏の顔。
```

这类系列信息非常适合做“可追踪线索”。

### 建议

在推送中展示：

```text
📚 系列：学級委員の僕だけが知る...
```

并在后续支持：

```text
/watchseries <series_id 或 series_url>
```

如果当前 RSS HTML 里系列链接可解析出 `series/<id>`，就可以把系列作为新的 target 类型。

### 价值

- 从“关注女优/片商”扩展到“关注题材系列”。
- 更符合实际看片偏好：很多时候题材系列比演员更稳定。
- RSS 已经包含系列文本和链接，数据基础存在。

## 建议四：磁力推荐升级为“版本排行榜”

### 问题

当前只展示一个“最优磁力”。

但 RSS 实际包含多条 magnet，每条都有：

- 文件名
- 文件大小
- 分享日期

样本里同一作品有多个版本：

- 1.79GB
- 2.52GB
- 3.73GB
- 5.59GB
- 7.72GB 中字版本

用户真正关心的是：

- 有没有中字
- 体积是否合适
- 是否太小像低清
- 是否太大不方便
- 分享日期是否较新

### 建议

不要只展示一个磁力，改成展示前 2-3 个推荐版本：

```text
🧲 推荐版本
1. 中字优先：7.72GB / 2026-05-04
2. 体积均衡：5.59GB / 2026-05-08
3. 小体积：2.52GB / 2026-05-10
```

每个版本仍用 `<code>` 包磁力链接，方便复制。

选择逻辑可以简单固定：

- 中字优先：命中 `字幕|中字|-C|CN|SUB`
- 均衡优先：4-8GB
- 小体积：2-4GB
- 最新分享：shareDate 最新

### 价值

- 比单个“最优磁力”更符合用户下载决策。
- 避免硬选一个版本选错。
- 不需要 AI，纯规则即可。

## 建议五：新增“样品图点评/看点摘要”

### 问题

当前已经发送封面 + 样品图，视觉信息很有价值，但文字没有总结“看点”。

RSS 的标题 + 类别 + 系列 + 样品图存在，可以生成一段很短的看点摘要。

### 建议

新增一句：

```text
🔥 看点：女教师题材，羞耻/校内露出路线，成熟系。
```

第一版可以不用看图，只用标签和标题规则生成：

- `女教師` + `羞恥` -> “女教师羞耻题材”
- `已婚婦女` + `成熟的女人` -> “成熟人妻系”
- `巨尻` -> “身材卖点偏巨尻”
- `DMM獨家` -> “DMM 独家”

如果以后要用 AI，也只把标题和标签给 AI，不需要传图片。

### 价值

- 用户扫一眼就知道主题。
- 比完整标题翻译更贴近决策。
- 可以减少对长标题翻译的依赖。

## 建议六：片商批量摘要改成“高价值条目索引”

### 问题

当前 label 摘要主要展示翻译后的标题列表。

但片商一次更新很多部时，用户更需要知道哪些条目值得点开，而不是读 10 个长标题翻译。

RSS 每条都能解析：

- 识别码
- 标题
- 演员
- 标签
- 系列
- 封面

### 建议

片商摘要不要只做标题列表，改成高价值索引：

```text
🏢 Madonna 批量更新：18 部

1) JUR-704 木下凛々子
   女教师 / 羞耻 / 巨尻

2) XXX-000 演员名
   人妻 / 成熟 / 高画质

3) YYY-000 演员名
   DMM独家 / 系列作

… 还有 15 部
```

其中演员可优先使用 RSS `author` / `creator`，类别用 `categories` 或 HTML genres。

### 价值

- 片商摘要从“标题翻译列表”升级为“可筛选索引”。
- 用户能快速判断哪些条目值得点。
- 大幅提升 label 订阅的存在价值。

## 建议七：新增“演员共演/演员列表展示”

### 问题

当前样本是单演员，但 HTML 的演员区域理论上可以有多名演员。

当前 parser 没有显式解析演员列表，只依赖 targetName 或 RSS author。

### 建议

解析 HTML 演员区：

```html
div.star-name a
```

得到：

```text
👥 演员：木下凛々子 / ...
```

如果作品中出现未订阅演员，可以作为后续扩展：

```text
➕ 关注该演员：/watchstar xxx
```

### 价值

- 共演作品信息更完整。
- 能发现新的关注对象。
- 对片商摘要尤其有用，因为 label feed 不是围绕单个演员。

## 建议八：新增“片商/系列/标签维度的用户偏好命中”

### 问题

现在 tracked target 只有 star/label。RSS 里其实还有标签、系列、制作商、发行商等维度。

用户偏好可能是：

- 只要某个女优出新作
- 只要 Madonna 某类题材
- 只要女教师/羞耻/人妻题材
- 只要某个系列

当前只能通过 star/label 间接覆盖。

### 建议

先不新增复杂订阅系统，只在推送里显示“命中原因”：

```text
🎯 命中原因：关注演员 木下凛々子；标签 女教師/羞恥 命中偏好
```

后续再支持偏好配置：

```json
{
  "favoriteGenres": ["女教師", "羞恥", "已婚婦女"],
  "favoriteMakers": ["マドンナ"],
  "favoriteSeries": ["..."]
}
```

### 价值

- 推送不只是“某目标更新”，而是告诉你为什么值得看。
- 为后续更智能的筛选打基础。
- 用户能更快做判断。

## 优先级建议

### P0：最值得先做

1. 作品档案字段：发行日期、时长、发行商、系列。
2. 口味命中卡：按类别标签分组展示。
3. 磁力版本排行榜：展示 2-3 个可选版本。

这三项全部基于现有 parser 已解析数据，改动小，用户价值直接。

### P1：提升片商订阅价值

4. 片商批量摘要改成“识别码 + 演员 + 标签”的高价值索引。
5. 解析演员列表，特别服务 label feed。

这能解决 label 摘要现在“标题列表信息密度不够”的问题。

### P2：偏好化和追踪扩展

6. 同系列追踪建议。
7. 标签/系列/制作商偏好命中。

这两项价值高，但需要新增一点配置或 target 类型，适合后续做。

## 不建议优先做

1. 不建议再围绕速度做功能设计。
   速度问题另有性能文档；这里应优先挖 RSS 内容价值。

2. 不建议优先增加更多外部数据源。
   当前 RSS 已经给了很多信息，先把已有数据用好。

3. 不建议优先让 AI 做复杂鉴黄/评分。
   第一版用规则整理标签和磁力版本即可，主路径更清晰。

4. 不建议把片商批量更新逐条详情推送。
   片商更新天然批量，应该做索引摘要，不应该刷屏。
