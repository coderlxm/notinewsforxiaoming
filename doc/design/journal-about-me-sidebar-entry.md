# Journal「关于我」入口与个人页面设计

## 1. 文档状态

- 状态：已实施，等待验收
- 目标阶段：部署后验收
- 本文只依据当前源码和本轮已经确认的产品方向整理。

## 2. 需求背景

公开首页目前通过固定侧边栏提供「生活 / 文章 / 兴趣」三个内容频道，移动端使用底部导航承载相同入口。访客能够按内容类型浏览信息流，但缺少一个稳定入口进一步了解站点主人并获取联系方式。

未来还计划在 Journal 中托管个人简历，但个人简历不应反过来主导当前「关于我」需求。当前最直接的需求仍然是：

- 访客能够快速知道站点主人是谁。
- 访客能够看到主动公开的联系方式。
- 页面保留未来进入完整个人简历的自然路径。

因此采用两层结构：首版实现轻量 About 页面，未来再增加独立的 Resume 二级页面。

## 3. 当前实现依据

当前源码表现为：

- 桌面公开页使用固定侧边栏，信息流是独立滚动区域。
- 侧边栏当前包含「生活 / 文章 / 兴趣」三个频道项。
- 移动端已经使用底部操作栏展示三个频道。
- 各公开频道和标签页面使用独立缓存实例，并保留各自的滚动位置。
- 站点公开资料已经包含头像和 Bio，并由现有设置页维护。
- 项目已有统一的公开页面外壳、路由解析和 ElMessage 能力。

## 4. 产品目标

### 4.1 首版目标

1. 访客可以从公开页面稳定找到「关于我」。
2. 「关于我」拥有可分享、可直接访问的独立 URL。
3. About 第一屏能够展示身份信息和联系方式。
4. 从信息流进入和返回时，不丢失原频道、标签、列表状态和滚动位置。
5. 桌面端继续保持固定侧边栏与独立内容滚动区域。
6. 移动端将「关于我」纳入现有底部导航。
7. 视觉继续沿用当前 Journal 的克制、个人化风格。

### 4.2 未来目标

1. 在 About 页面提供「查看个人简历」入口。
2. 使用独立的 /about/resume 页面承载完整简历。
3. 简历页面支持直接分享、打印和可选的 PDF 下载。
4. 增加简历能力时不改变全局导航结构。

## 5. 非目标

首版不包含：

- 完整个人简历。
- 简历 Markdown 渲染。
- 简历打印样式或 PDF 下载。
- 站内私信或留言表单。
- 验证码、反垃圾和消息通知系统。
- 访客账号、关注关系或访问统计。
- 通用页面搭建器。
- 富文本个人主页编辑器。
- 微信二维码上传和裁剪。
- 名片弹层与独立 About 页面两套展示。

## 6. 信息架构

整体结构为：

    关于我
    ├── /about
    │   ├── 头像、姓名、Bio
    │   ├── 简短自我介绍
    │   ├── 联系方式
    │   └── 查看个人简历入口（简历上线后展示）
    │
    └── /about/resume
        ├── 工作经历
        ├── 项目经历
        ├── 技能
        ├── 教育经历
        └── 打印或 PDF（未来能力）

全局侧边栏和移动端底栏只增加一个「关于我」入口，不增加「简历」入口。简历属于 About 的二级内容，可通过 About 页面进入，也可以使用独立 URL 直接访问。

## 7. 呈现方式决策

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 个人名片弹层 | 联系路径短；不改变路由 | 不可分享；移动端底栏打开弹层语义奇怪；未来会与页面重复 | 不采用 |
| 单一 About 长页面 | 实现直接；所有内容集中 | 简历容易压过个人介绍和联系方式 | 不采用 |
| 轻量 About + 独立 Resume | 当前需求轻；未来扩展清晰；全局导航不膨胀 | 未来增加一个二级路由 | 采用 |

## 8. 首版推荐方案

采用「侧边栏或底栏入口 + 轻量 /about 页面」。

点击「关于我」后：

- URL 切换为 /about。
- 全局 Header 和公开页面外壳保持不变。
- 桌面侧边栏保持固定，主内容滚动区域切换为 About 页面。
- 移动端底部导航保持固定，About 内容在上方独立滚动。
- 当前 Feed 进入停用状态但不销毁。
- 浏览器返回或重新选择频道后，恢复之前的频道、标签和滚动位置。

About 页面只负责个人身份、简短介绍和联系方式，不在首版放入空简历区块、不可用按钮或“敬请期待”等占位。

## 9. 导航设计

### 9.1 桌面端

侧边栏划分为上下两个区域：

- 上部：生活、文章、兴趣频道导航。
- 下部：关于我。

「关于我」固定在侧边栏底部，不随频道数量挤在顶部。入口复用频道项的高度、圆角、字号、悬停背景和左右内边距，并通过额外间距与频道组分隔。

交互状态：

- 访问生活、文章或兴趣时，对应频道保持选中。
- 访问 /about 或 /about/resume 时，仅「关于我」显示选中态。
- 「关于我」使用 aria-current="page"，不使用弹层语义。
- 点击已经激活的「关于我」回到 /about。

PublicChannelNavigation 不应把 About 伪装成新的 JournalChannel，而应能够单独表达当前是否处于 About 范围。

### 9.2 移动端

现有底部导航由三项扩展为四项：

    生活    文章    兴趣    关于我

要求：

- 四项使用相同的点击高度、字体和激活背景。
- 首版继续使用文字，不为 About 单独引入风格不一致的图标。
- 访问 /about 或 /about/resume 时，仅「关于我」显示激活态。
- 底栏继续适配安全区。
- About 页面滚动不影响底栏位置。

## 10. About 页面内容

### 10.1 身份区

展示：

- 当前公开头像。
- 固定名称「小明同学」。
- 当前公开 Bio。

头像和 Bio 直接复用现有站点公开资料，不维护第二套相同字段。

### 10.2 自我介绍

About 页面可以提供一段比 Bio 稍长的自我介绍，用于表达：

- 当前所在城市或生活状态。
- 工作和学习方向。
- 主要兴趣。
- 希望通过 Journal 记录什么。

首版保持一至数个自然段，不演变为富文本个人主页。该内容与首页 Bio 语义不同，应使用独立字段或独立内容来源，不覆盖 Bio。

### 10.3 联系方式

联系方式紧跟身份或自我介绍区域，确保普通移动端首屏或轻微滚动后即可看到。

建议支持：

| 类型 | 展示示例 | 操作 |
| --- | --- | --- |
| Telegram | @xiaoming | 打开 Telegram 链接 |
| Email | name@example.com | 打开邮件客户端并允许复制 |
| 微信 | 微信号 | 复制微信号 |
| GitHub | github.com/xxx | 在新标签页打开 |
| 个人链接 | 自定义名称或域名 | 在新标签页打开 |

只有填写并启用的项目才公开展示，不显示空占位。

### 10.4 简历入口

首版没有简历内容时，不展示简历入口。

未来 /about/resume 上线后，About 页面增加一个克制的「查看个人简历」入口：

- 不在第一屏使用大面积职业化宣传。
- 不展示简历内容摘要列表。
- 入口明确说明将进入完整简历。
- 点击后进入 /about/resume。

## 11. 联系方式数据设计

头像、Bio 和联系方式属于站点公开资料。

建议增加：

    interface SiteContactItem {
      kind: 'telegram' | 'email' | 'wechat' | 'github' | 'website';
      label: string;
      value: string;
      url: string | null;
      enabled: boolean;
    }

约束：

- kind 使用有限枚举，用于决定默认行为。
- label 是访客看到的渠道名称。
- value 是对外展示和复制的内容。
- url 只用于可跳转渠道。
- enabled 控制是否公开。
- 首版使用固定渠道顺序，不增加拖拽排序。

站点设置页在头像和 Bio 之后增加「联系方式」区域。保存后仍更新同一份公开资料。

自我介绍不建议塞入 contactItems。实施时可根据最终维护方式，在独立字段和受版本管理的短内容文件之间选择。

## 12. 首版路由与状态

新增公开路由：

    /about

路由行为：

- 可直接访问和刷新。
- 可使用浏览器前进、后退。
- 页面标题表达「关于我」。
- 不要求管理员身份。
- 不影响朋友投稿和私有资产路由。

Feed 状态处理：

- 进入 About 前保存当前公开频道、标签和滚动位置。
- Feed 实例继续由现有 KeepAlive 体系管理。
- 返回时复用当前频道与标签对应的缓存实例。
- About 不进入公开 Feed 的频道枚举，也不占用 Feed 缓存数量。

## 13. 首版页面布局

### 13.1 桌面端

- 侧边栏保持固定。
- 只允许主内容区域滚动。
- About 页面使用适合阅读的最大宽度，不随工作区无限拉宽。
- 身份区与联系方式可以形成上下区块，不使用抽屉布局。
- 页面内容较少时保持自然留白，但不通过巨型卡片强行填满高度。

### 13.2 移动端

- Header 继续沿用现有滚动隐藏行为。
- 底部导航始终保留。
- About 内容采用单列排列。
- 页面底部为底栏和安全区预留空间。
- 联系方式具有足够的触控高度。

## 14. 联系操作

- Telegram、GitHub 和个人链接在新标签页打开。
- Email 支持打开邮件客户端，也提供复制操作。
- 微信点击后复制微信号。
- 复制成功复用项目现有 ElMessage。
- 外部链接显示明确的跳转语义。
- 不对联系方式请求增加站内代理或跳转服务。

## 15. 视觉方向

About 页面保持当前 Journal 的低饱和视觉：

- 页面使用当前工作区宽度和间距变量。
- 身份区保持轻量，不模拟社交平台资料卡。
- 头像建议为 72px 至 88px。
- 名称使用当前正文主色和较高字重。
- Bio 和自我介绍自然换行，不使用首页横向滚动效果。
- 联系方式使用轻量分隔或浅色行容器。
- 强调色继续使用当前红色变量。
- 不因未来存在简历而提前加入时间线、技能标签墙等职业化装饰。

## 16. 首版组件边界

### PublicChannelNavigation.vue

- 负责桌面侧边栏和移动端底栏。
- 增加「关于我」入口。
- 接收当前频道和 About 激活状态。
- 分别发出频道选择和 About 选择事件。
- 不直接管理 About 页面内容。

### AboutView.vue

- 负责 About 页面整体组合。
- 读取现有公开资料。
- 组合身份、自我介绍和联系方式。
- 不管理 Feed 状态。

### AboutContactList.vue

- 负责联系方式展示、复制和外部跳转。
- 通过 props 接收已启用的联系方式。
- 不直接读取全局 Store。

### App.vue

- 解析 /about。
- 在公开页面外壳中切换 Feed 与 About。
- 管理公开 Feed 的停用和恢复。
- 不把 About 建模为新的 Feed 频道。

## 18. 未来简历方案

简历内容准备完成后新增：

    /about/resume

未来简历页负责：

- 个人概述。
- 工作经历。
- 项目经历。
- 技能。
- 教育经历。
- 最近更新时间。
- 打印样式。
- 可选的 PDF 下载。

建议使用一份受版本管理的 Markdown 内容文件作为简历来源。简历不并入 JournalSiteProfile，也不存成不断扩张的 JSON 字段。

Markdown 使用固定标题层级表达简历结构，不允许任意 HTML。实施时优先复用项目已有的文章渲染能力；如现有能力不适用，再核对当前依赖后选择成熟的 Markdown 解析库。

未来 Resume 页面不增加新的全局导航项。访问 /about/resume 时，「关于我」继续保持激活状态。

## 19. 首版验收场景

1. 访客可以直接访问 /about。
2. 桌面端「关于我」稳定位于侧边栏底部。
3. 移动端底栏稳定展示四个入口。
4. About 激活时三个内容频道均不显示选中态。
5. 页面显示与首页一致的头像和 Bio。
6. 页面展示独立的简短自我介绍。
7. 只展示已启用且内容完整的联系方式。
8. 联系方式跳转和复制操作提供明确反馈。
9. 首版没有简历时不展示空简历入口。
10. 从任意频道和标签进入 About 后返回，原列表与滚动位置保持不变。
11. About 页面可以通过浏览器前进和后退正常切换。

## 20. 已确认决策

1. 全局只增加一个「关于我」入口。
2. 首版使用轻量 /about 页面，不使用名片弹层。
3. 桌面端入口位于侧边栏底部。
4. 移动端入口位于现有底部导航。
5. 头像和 Bio 复用现有公开资料。
6. 联系方式并入现有公开资料。
7. 完整简历不进入首版。
8. 未来简历使用独立 /about/resume 页面。
9. 简历页面不增加新的全局导航项。
