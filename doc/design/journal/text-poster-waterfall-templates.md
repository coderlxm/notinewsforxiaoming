# 纯文字瀑布卡片七套画报模板改造方案

## 一、目标

将无附件的普通文字记录从目前单一的文字卡片，改造成具有画报主体的瀑布流卡片，并提供 7 套视觉模板。每套模板同时设计日间和暗色版本，使纯文字内容在瀑布流中具备接近图片内容的视觉吸引力，同时控制卡片高度。

改造后的纯文字卡片结构统一为：

```text
日期与管理操作
画报模板
最多两行的正文摘要
标签
```

正文摘要超过两行时由浏览器自然显示省略号，不再按固定字符数提前截断。

## 二、适用范围

只有同时满足以下条件的记录使用画报卡片：

- `bodyFormat === 'plain'`
- `assets.length === 0`
- `contentText.trim()` 不为空

富文本文章、图片、视频、音频和文件记录继续使用现有卡片，不改变其展示路径。

本次只改变展示层，不新增接口、数据库字段或后台配置。管理操作、标签筛选、打开详情、编辑和删除交互继续沿用现有行为。

## 三、模板分配规则

### 3.1 稳定随机，而非每次重新随机

模板由记录自身稳定标识计算：

```text
templateIndex = stableHash(entry.publicId) % 7
```

这样既能形成随机分布，又能保证：

- 同一条记录刷新后不会换模板；
- 搜索、筛选、翻页和切换视图后不会换模板；
- 卡片进入详情时继续使用同一套视觉风格；
- 不需要在数据库保存模板编号。

模板选择应实现为无状态纯函数，不使用组件本地随机数、生命周期赋值或监听器。

### 3.2 分布原则

七套模板采用等概率分配，不根据文字内容做语义分类。这样不会引入内容分析、关键词规则或未来维护成本，也避免同类内容长期集中到同一风格。

## 四、七套模板方向

七套模板使用相同的信息内容：正文、可选装饰符号、日期、作者标识。区别集中在构图、字体层级、色彩和装饰语言，避免七套模板只是换背景色。

| 编号 | 模板名称 | 日间模式 | 暗色模式 | 主要构图 |
| --- | --- | --- | --- | --- |
| 1 | 编辑纸 | 暖灰纸张、深墨文字、红色编辑线 | 炭黑纸张、米白文字、暗红强调 | 当前画报风格的延续，正文居中，大型引号作底纹 |
| 2 | 书页 | 象牙白、墨黑、书脊阴影 | 深棕黑、暖白、铜色细线 | 偏文学书页，较宽留白，页码与章节标识 |
| 3 | 瑞士网格 | 冷白、黑字、高饱和红块 | 石墨灰、白字、低亮红块 | 强网格、左对齐、大字号编号和几何分割 |
| 4 | 档案卡 | 浅卡其、深褐、印章红 | 深橄榄灰、浅卡其、暗橙红 | 档案编号、细边框、打字机式辅助信息 |
| 5 | 夜场字幕 | 雾白底、深蓝黑字、紫红光晕 | 近黑底、灰白字、紫红微光 | 电影字幕式居中构图，留出呼吸感和时间标记 |
| 6 | 手账便笺 | 淡米黄、铅笔灰、胶带色块 | 深蓝灰、暖灰字、低亮胶带色 | 轻微横线、贴纸和手写感装饰，但正文保持可读 |
| 7 | 新闻标题 | 报纸白、黑字、酒红分隔线 | 深灰黑、灰白字、暗红分隔线 | 报刊头版式层级，日期栏、栏目号和标题化正文 |

每套暗色版本都单独定义背景、正文、辅助文字、强调色和装饰透明度，不使用简单反色滤镜。

## 五、卡片内容规则

### 5.1 画报内文字

画报继续根据正文长度调整字号，但所有模板共享三档规则，避免每套模板产生不同的截断结果：

- 短文本：突出单句，字号最大；
- 中等文本：保持海报标题感；
- 长文本：缩小字号并限制画报内部最大行数；
- 超出画报容量时显示省略号，不让画报纵向继续增长。

画报维持固定比例，瀑布流中建议使用 `4 / 5`，从而让七种视觉保持统一面积，避免长文字重新把卡片撑高。

### 5.2 卡片底部摘要

画报下方仍展示正文摘要，方便快速浏览和命中搜索结果。摘要规则为：

- 固定最多两行；
- 超出两行自动显示 `…`；
- 合并正文中的连续空白和换行，避免空行占据摘要行数；
- 不再使用当前固定 72 个字符的截断逻辑；
- 标签维持现有展示与点击行为。

这里使用 CSS 多行截断，使不同屏幕宽度下都以实际两行作为边界，而不是按中文字符数猜测可见长度。

## 六、组件设计

### 6.1 组件边界

| 模块 | 单一职责 | 输入与输出 |
| --- | --- | --- |
| `EntryCard.vue` | 判断记录类型并组合日期栏、画报、摘要、标签和管理操作 | 输入现有 `entry` 与权限属性；继续发出现有操作事件 |
| `JournalTextPoster.vue` | 根据记录渲染稳定模板及对应日间/暗色样式 | 输入 `entry`、新增 `display: 'card' \| 'detail'`；无业务事件 |
| `textPosterTemplate.ts` | 根据 `publicId` 计算 7 个模板之一 | 输入稳定字符串，输出模板名称；纯函数、无响应式状态 |

七套模板不拆成七个 Vue 组件。它们的信息结构相同，使用一个画报组件和七个模板修饰类即可，减少重复模板代码。只有确实改变 DOM 信息结构的装饰元素才由模板类控制显隐。

### 6.2 数据流

```text
WaterfallFeed
  → EntryCard(entry)
    → 判断是否为纯文字记录
    → JournalTextPoster(entry, display="card")
      → resolveTextPosterTemplate(entry.publicId)
      → 输出稳定模板类
```

详情页继续复用 `JournalTextPoster`，并传入 `display="detail"`。同一条记录在瀑布流和详情页采用相同模板，仅根据容器尺寸调整排版。

### 6.3 样式组织

画报组件保留一套基础布局，并用模板类定义 CSS 变量：

```text
基础层：比例、溢出、正文尺寸档位、页眉页脚结构
模板层：背景、字体组合、构图、强调色和装饰元素
暗色层：每个模板对应的暗色变量
尺寸层：card 与 detail 的字号和留白差异
```

当前项目使用 `prefers-color-scheme: dark`，七套模板继续沿用该机制，不另建主题状态。

## 七、与现有瀑布布局的关系

- 画报具有固定比例，首次布局即可得到稳定高度，减少瀑布重新排版；
- 模板完全使用 CSS，不加载模板背景图片；
- 模板编号由纯函数同步计算，不引入异步加载；
- 卡片整体仍由现有 `@egjs/grid` 管理，不修改翻页、筛选和缓存行为；
- 卡片点击区域、操作菜单和标签按钮的事件边界保持不变。

## 八、实施顺序

1. 提取稳定模板计算函数，定义七个明确的模板名称类型。
2. 将 `JournalTextPoster` 扩展为 `card/detail` 两种尺寸，并加入七套日间与暗色设计。
3. 在 `EntryCard` 中增加纯文字记录判断和画报渲染，保留现有管理操作结构。
4. 将纯文字卡片底部正文改为两行 CSS 截断，移除该路径上的 72 字符截断。
5. 让详情页复用相同模板编号，保证打开前后视觉连续。
6. 调整瀑布卡片间距，使画报、两行摘要和标签形成紧凑但清晰的层级。

## 九、完成标准

- 瀑布流中的纯文字记录稳定分布在 7 套画报模板中；
- 每套模板均有独立的日间和暗色配色；
- 同一条记录在刷新、筛选、翻页以及打开详情后保持同一模板；
- 纯文字卡片画报高度不随正文无限增长；
- 画报下方正文最多显示两行，超出部分显示省略号；
- 图片、视频、音频、文件和富文本文章卡片不受影响；
- 现有编辑、删除、标签筛选、可见性和频道操作保持原路径。

## 十、不纳入本次范围

- 管理员手动选择或更换模板；
- 将模板编号写入数据库；
- 根据内容情绪或关键词智能选择模板；
- 为模板加载外部背景图片、字体或生成式图片；
- 改造表格视图或详情页的信息管理交互。
