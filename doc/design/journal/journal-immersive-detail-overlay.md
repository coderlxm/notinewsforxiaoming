# Journal 沉浸式详情卡片设计方案

## 1. 文档状态

- 状态：决策已确认，首版已实施
- 范围：Journal Web 的公开信息流、个人资产信息流与普通记录详情
- 核心形态：桌面端沉浸式详情弹层，移动端全屏详情
- 不涉及：评论、点赞、收藏、关注、推荐算法和 Telegram 数据结构
- 产品定位：借鉴小红书的媒体与文字分区，不复制其社交产品结构

## 2. 当前实现与设计判断

### 2.1 当前源码行为

- `App.vue` 使用轻量自有路由，公开详情地址为 `/p/:publicId`。
- `FeedView.vue` 点击公开卡片后会卸载当前展示分支，切换到独立详情页并再次请求详情。
- 公开与私有信息流已由 `KeepAlive` 保存组件状态，返回后可以恢复瀑布流与滚动位置。
- 信息流接口返回的 `JournalEntry` 已包含完整正文、富文本 JSON、标签和全部资产。用户从卡片进入时，现有记录数据足以立即组成详情，不需要重复等待相同内容。
- `MediaGallery.vue` 的详情模式会纵向展开全部媒体，适合普通页面阅读，不适合桌面弹层中的固定媒体舞台。
- 私有普通记录只有公开状态时才能进入 `/p/:publicId`；私有富文本文章点击后直接进入编辑页。因此当前两类信息流的详情行为并不一致。

### 2.2 借鉴边界

本方案借鉴截图中的三个有效思路：

1. 点击卡片后不离开信息流语境，详情作为上层内容出现；
2. 桌面宽屏把视觉媒体与文字阅读分成左右两个明确区域；
3. 媒体区与文字区拥有独立、稳定的空间，避免长文把图片推离视线。

不直接照搬：

- 关注按钮、作者社交关系、互动计数和评论区；
- 固定黑底与小红书品牌色；
- 所有内容都强行左右分栏；
- 为短文本保留大片无意义的空媒体区。

## 3. 目标与非目标

### 3.1 目标

1. 桌面端点击普通媒体记录后，以沉浸式弹层展示，背景仍是进入前的信息流。
2. 图片或视频位于左侧大媒体舞台，正文、时间、标签和管理动作位于右侧阅读栏。
3. 关闭详情后回到原信息流、原筛选和原滚动位置，不重新读取、不重新排版。
4. 地址栏继续反映当前详情，浏览器前进、后退、刷新和复制链接保持有效。
5. 公开记录与个人资产使用同一详情组件；私有模式只增加已有管理动作，不复制一套界面。
6. 不适合左右分栏的内容使用对应阅读形态，避免为了统一而损害阅读。

### 3.2 非目标

- 首版不加入评论、点赞、收藏和分享统计。
- 不做卡片到详情的共享元素飞入动画。
- 不引入 Vue Router、全局状态库或新的弹窗组件库。
- 不改变 Telegram 采集、记录存储和媒体文件存储方式。
- 不让弹层承担富文本文章编辑；编辑继续使用现有独立编辑页。
- 不使用任何 `requestAnimationFrame` 或依赖逐帧测量的实现。

## 4. 推荐形态

### 4.1 桌面端：媒体详情弹层

适用条件：视口宽度不小于 `960px`，且记录至少有一项图片、视频、动画或视频贴纸。

```text
信息流背景（保留当前位置，降低亮度）
┌──────────────────────────────────────────────────────────────┐
│                  ┌────────────────────────────────────────┐  │
│                  │                │ 作者 / 时间       关闭 │  │
│                  │                │                    │  │
│                  │   当前媒体     │ 完整正文           │  │
│                  │   contain      │                    │  │
│                  │                │ 结构化信息         │  │
│                  │                │ #标签              │  │
│                  │  ‹  2 / 6  ›   │                    │  │
│                  │  缩略媒体导航  │ 私有管理动作       │  │
│                  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

- 弹层宽度：`min(1440px, calc(100vw - 48px))`。
- 弹层高度：`min(880px, calc(100dvh - 48px))`。
- 左右比例：媒体区约 `62%`，文字区约 `38%`；文字区最小宽度 `360px`。
- 左侧使用墨灰色媒体舞台，图片默认 `object-fit: contain`，不为了填满空间裁掉生活影像。
- 右侧延续当前纸张、墨色与石榴红视觉，保持个人档案感，而不是复制截图中的纯黑社交面板。
- 弹层圆角、边框与阴影只负责从背景中建立层级，不新增玻璃拟态或高饱和渐变。

### 4.2 桌面端：无视觉媒体详情

纯文字、语音、音频和文件记录不展示空的左栏，改为居中的单栏详情卡：

- 最大宽度约 `760px`；
- 正文、结构化字段、音频与文件附件连续排列；
- 短句可延续现有衬线大字与淡石榴色纸张；
- 弹层的打开、关闭、路由和背景保留规则与媒体详情一致。

### 4.3 富文本文章

富文本文章继续使用当前独立阅读页，不塞入右侧窄栏：

- 长文章、文中图片、标题层级和代码块需要连续阅读宽度；
- 从公开信息流点击文章仍进入 `/p/:publicId` 阅读页；
- 从个人资产点击文章默认打开只读详情，右侧或顶部提供明确“编辑文章”入口，再进入现有编辑页；
- 首版不做“封面在左、全文在右”的文章形态，避免长文阅读区过窄且内部滚动过长。

这意味着详情系统按内容职责选择布局，而不是按同一个模板强行渲染所有记录。

### 4.4 移动端

小于 `960px` 时不显示桌面左右分栏：

- 使用占满视口的全屏详情层；
- 图片或视频在上，正文和标签在下，共用一条自然滚动轴；
- 顶部保留返回按钮与日期，按钮避让 `env(safe-area-inset-top)`；
- 底部内容避让 `env(safe-area-inset-bottom)`；
- 不出现桌面背景留白和双栏内部滚动。

## 5. 媒体舞台

### 5.1 媒体分类

详情布局先从 `entry.assets` 派生两组内容：

- 视觉媒体：图片、视频、动画、图片/视频贴纸；
- 附属媒体：语音、音频和文件。

只有视觉媒体触发桌面左右分栏。语音和文件放在右侧正文之后，避免在左侧媒体舞台中形成难以理解的空播放器区域。

### 5.2 单项媒体

- 图片完整居中，保留原始比例；
- 视频使用原生控件和 `preload="metadata"`；
- 圆形视频继续显示为圆形，但外部舞台仍保持矩形；
- 贴纸限制最大尺寸，不把低分辨率素材放大到失真。

### 5.3 多项媒体

- 左侧一次只显示一个主媒体，不再纵向铺开所有图片；
- 底部提供上一项、下一项、`当前序号 / 总数` 与紧凑缩略图导航；
- 可复用项目已经安装的 Vant `Swipe` / `SwipeItem` 管理切换，不再引入另一套轮播库；
- 弹框尺寸跟随当前图片比例变化，不以第一张图片的比例固定整组媒体；
- 尺寸计算为多媒体控制区预留固定高度，图片区域保持真实宽高比；
- 当前图片始终完整显示；合理比例通过弹框自适应消除留边，极端比例或缺少尺寸时允许留边但禁止裁图；
- 图片切换不重置右侧正文滚动位置；
- 视频播放时切换到其他媒体，直接暂停离开的媒体，不在后台继续播放。

## 6. 右侧阅读栏

### 6.1 内容顺序

```text
小明同学 / 日期时间 / 公开或私有状态
正文或标题
结构化字段
语音、音频、文件
标签
私有管理动作（仅个人资产）
```

- 不重复展示站点简介、关注按钮或虚构互动数据。
- 正文保留 Telegram 原始换行，长文本允许自然换行。
- `entities` 与 `caption_entities` 继续作为 Telegram 渲染元数据隐藏，不回到界面。
- 右栏独立滚动，滚动条使用现有主题颜色；媒体区不随长正文移动。
- 私有模式的编辑、置顶、可见性和永久删除继续复用现有业务动作与二次确认。

### 6.2 短内容的空间处理

右栏内容不足一屏时从顶部自然排版，不做垂直居中，也不人为撑开段落。管理动作可以位于底部固定操作区，但正文区不因操作区而改变宽度。

## 7. 路由、历史与信息流保留

### 7.1 从信息流打开

公开信息流：

1. 卡片把完整 `JournalEntry` 作为打开事件上送给 `App.vue`；
2. `App.vue` 记录来源信息流 key 和该条记录，并把地址推进到 `/p/:publicId`；
3. 原 `FeedView` 继续渲染在弹层下方，不退出 `KeepAlive`，也不改变 `.app-scroll.scrollTop`；
4. 弹层直接使用信息流已有记录渲染，因此点击后立即成立，不再次显示“正在展开记录…”；
5. 浏览器后退或点击关闭只移除详情层，原瀑布流原地可用。

个人资产：

1. 普通记录与富文本文章都把完整记录上送；
2. 地址使用 `/me?entry=:id` 表达当前私有详情；
3. 详情层复用同一个组件，并显示该记录已有的管理入口；
4. 富文本文章的“编辑文章”再进入 `/me/articles/:id/edit`，不再让整张卡片点击直接等同于编辑。

### 7.2 直接访问链接

- 直接访问或刷新 `/p/:publicId` 时，先请求公开详情并判断记录类型：富文本文章继续使用独立阅读页，普通记录挂载公开信息流背景并打开详情弹层。
- 普通记录弹层直接复用类型判断时得到的完整记录，不再次请求详情。
- 直接访问或刷新 `/me?entry=:id` 时，先完成现有登录流程，再通过一个按 ID 读取私有记录的接口展示详情。
- 公开外链和私有链接使用不同标识与鉴权边界，不把私有数字 ID 暴露到公开接口。

### 7.3 关闭规则

- 从信息流打开：关闭按钮、点击遮罩或按 `Escape` 均执行浏览器后退。
- 从普通记录直接链接进入：关闭弹层导航到 `/`；富文本文章的返回入口导航到 `/`；私有直接链接返回 `/me`。
- 浏览器前进可以重新打开刚才的详情。
- 打开弹层时不执行当前 `navigate()` 中的滚动归零逻辑。

## 8. 组件与代码边界

### 8.1 新增组件

| 文件 | 职责 |
| --- | --- |
| `web/src/components/journal/JournalDetailOverlay.vue` | 使用 Vue `Teleport` 与原生 `<dialog>` 提供弹层、遮罩、焦点、关闭事件和响应式外壳 |
| `web/src/components/journal/JournalDetailLayout.vue` | 根据视觉媒体、纯文本和附件选择双栏或单栏布局 |
| `web/src/components/journal/JournalMediaStage.vue` | 主媒体、切换、序号、缩略图和媒体暂停 |
| `web/src/components/journal/JournalDetailContent.vue` | 作者时间、正文、结构化字段、附件、标签与私有动作 |

不建立全站 Modal 框架；这些组件只服务 Journal 详情主路径。

### 8.2 调整现有组件

- `App.vue`
  - 增加当前详情上下文：记录、来源路由与打开方式；
  - 详情来自信息流时继续渲染来源 `FeedView`，在其上挂载详情层；
  - 直接链接取得记录后按正文类型选择弹层详情或独立文章阅读页。
- `FeedView.vue`
  - 统一向上发出完整记录，而不只发 `publicId`；
  - 私有卡片点击改为打开只读详情，编辑动作保持明确入口；
  - 现有公开详情读取用于解析直接链接，普通记录随后复用结果进入弹层，富文本文章留在独立阅读页。
- `WaterfallFeed.vue`、`EntryCard.vue`、`ArticleCardContent.vue`
  - 统一 `open-entry` 事件载荷为 `JournalEntry`；
  - 卡片内部按钮、链接、音视频控件继续阻止触发整卡打开。
- `MediaGallery.vue`
  - 保持信息流卡片媒体布局；详情舞台由新组件承担，避免向一个组件塞入互斥布局。
- `useJournalApi.ts`
  - 增加按 ID 读取私有记录的动作；公开直接链接继续使用现有 `loadPublicDetail()`。

### 8.3 服务端最小调整

新增一个登录后可用的私有详情接口，按记录数字 ID 返回现有 `JournalEntry` 结构。它只用于刷新或直接进入 `/me?entry=:id`，从个人资产信息流点击时不重复调用。

不新增详情缓存、预取、同步状态机或第二份详情数据模型。

## 9. 弹层行为与可访问性

- 使用原生 `<dialog>.showModal()` 建立真正的模态层，背景由浏览器置为不可交互；Vue `Teleport` 将其放到 `body`，避开应用外壳的滚动与层叠上下文。
- 弹层提供可感知标题，关闭图标按钮带 `aria-label="关闭详情"`。
- 打开后焦点进入关闭按钮；关闭后焦点回到原卡片。
- `Escape`、遮罩点击和关闭按钮使用同一关闭事件，不形成三套状态。
- 背景 `.app-scroll` 在弹层期间停止滚动；弹层内容使用 `overscroll-behavior: contain`，防止移动端滚动穿透。
- 上一项、下一项使用真实 `<button>`，带可见焦点和明确 `aria-label`。
- 图片保留合适的替代文本；Telegram 没有可靠描述时使用空替代文本，不拿文件名冒充内容描述。
- 弹层不禁止页面缩放，不拦截浏览器返回键。

## 10. 动画与状态

### 10.1 打开与关闭

- 遮罩：`opacity`，`160ms`；
- 面板：`opacity + translateY(8px) + scale(0.985)`，`220ms`；
- 关闭使用相反方向，时长 `160ms`；
- 只动画 `opacity` 和 `transform`，不动画宽高、边距或定位；
- 系统开启减少动态效果时移除位移与缩放，只保留近乎即时的显隐。

实现依靠 Vue 生命周期、原生 dialog 事件、CSS transition 和 `transitionend`，严禁使用 `requestAnimationFrame`。

### 10.2 内容读取

- 从信息流打开时使用已经存在的完整记录，详情直接入场。
- 直接访问公开或私有详情链接时，复用现有 `JournalLoading` 的 Reading 形态。
- 读取错误直接显示在详情阅读区，不关闭弹层、不显示空白假内容。
- 媒体自己的加载状态由原生图片、视频和音频元素表达，不增加全局 Loading。

## 11. 视觉细节

### 11.1 浅色模式

- 遮罩：接近墨色的半透明层，背景仍能辨认但不抢内容；
- 媒体区：`#20201e` 附近的墨灰；
- 文字区：现有 `--surface-card`；
- 分隔：使用 `--border-subtle`；
- 当前媒体序号和选中缩略图使用 `--accent`。

### 11.2 深色模式

- 媒体区比右栏略深，避免整块纯黑吞掉边界；
- 右栏继续使用现有暖墨灰；
- 原生 `<dialog>` 显式设置前景色与背景色；
- 滚动条沿用当前 `scrollbar-color`，不出现系统亮色滚动条。

### 11.3 关闭按钮

- 点击区域至少 `44px × 44px`；
- 桌面端位于右栏顶部，不悬浮到屏幕边缘；
- 移动端放入安全区内的顶栏；
- 不使用文字“X”，使用简单 SVG 图标并标记为装饰，按钮本身提供名称。

## 12. 实施顺序

### 阶段一：公开普通记录

1. 建立 `JournalDetailOverlay` 与双栏/单栏详情布局；
2. 统一普通卡片的 `open-entry` 事件；
3. 让 `App.vue` 在 `/p/:publicId` 的信息流打开场景中保留背景 Feed；
4. 完成图片、视频、多媒体切换和关闭行为；
5. 公开链接直接访问时按正文类型进入普通记录弹层或富文本文章阅读页。

### 阶段二：个人资产一致性

1. 增加私有详情读取接口与 `/me?entry=:id`；
2. 私有卡片整卡打开详情，管理菜单继续独立响应；
3. 普通记录在详情内复用编辑、可见性、置顶和永久删除；
4. 富文本文章以只读详情打开，并提供明确编辑入口。

### 阶段三：细节收口

1. 完成移动端全屏形态与安全区；
2. 处理媒体切换时的视频暂停；
3. 统一浅色、深色、焦点和减少动态效果；
4. 删除被新弹层路径取代的详情卡片专用样式，避免长期保留两套普通详情实现。

## 13. 验收功能清单

### 13.1 公开信息流

- 点击带图片或视频的普通卡片，桌面端出现左媒体、右文字的详情弹层。
- 点击纯文字、语音或文件记录，出现不含空媒体栏的单栏详情弹层。
- 地址切换到对应 `/p/:publicId`，浏览器前进和后退有效。
- 关闭后仍位于原滚动位置，卡片布局不重新计算为初始状态。
- 复制普通记录详情地址后直接打开，能在公开信息流背景上进入详情弹层；富文本文章仍进入独立阅读页。

### 13.2 个人资产

- 私有与公开普通记录都可整卡打开详情。
- 私有记录不会通过公开详情接口读取。
- 卡片管理菜单、音视频控件、标签和文件链接不会误触发整卡打开。
- 私有详情可执行现有编辑、置顶、可见性和永久删除。
- 富文本文章可从只读详情进入编辑页。

### 13.3 交互与布局

- 多项媒体可切换，序号准确，离开的媒体不会继续播放。
- 右栏长正文独立滚动，背景信息流和左侧媒体不随之移动。
- 移动端为单轴全屏详情，不出现桌面双栏挤压。
- `Escape`、遮罩和关闭按钮行为一致，焦点可进入并返回原卡片。
- 深色模式没有亮色系统滚动条，减少动态效果设置得到尊重。

## 14. 方案取舍

### 14.1 优点

- 小红书式左右分区只应用在最适合的媒体记录上，生活照片与文字关系更清晰。
- 信息流记录直接作为详情数据，打开速度快，也避免重复 Loading。
- 背景 Feed 始终保留，返回位置由真实组件状态保证，不依赖延时和滚动时序技巧。
- URL、浏览器历史和公开分享链接继续成立，弹层不是只能从首页进入的临时 UI。
- 公开与私有共用详情组件，长期不会形成两套视觉与交互。

### 14.2 成本与限制

- `App.vue` 需要从单一互斥页面渲染，调整为“背景 Feed + 可选详情层”，路由编排会比当前多一个明确的详情上下文。
- 私有详情要做到刷新直达，需要增加一个很小的鉴权 API。
- 多媒体详情需要独立媒体舞台，不能直接复用当前纵向 `MediaGallery`。
- 富文本文章仍使用阅读页，因此详情交互会按内容类型有所区别；这是为阅读质量保留的刻意差异。

## 15. Review 决策点

建议按本文默认方案确认以下三点：

1. 左右分栏只用于包含图片或视频的普通记录；富文本文章保留独立阅读页。 决策： 同意该建议
2. 个人资产也采用详情弹层，整卡点击从“编辑文章”调整为“查看详情”，编辑成为明确操作。 决策： 同意该建议
3. 私有详情地址使用 `/me?entry=:id`，并增加登录后按 ID 读取记录的最小接口。 决策： 同意该建议

这三个决定确认后，实施范围和组件边界即可固定，不需要再引入新的架构选择。
