# Journal 公开频道标签栏需求文档

## 1. 文档状态

- 阶段：初版需求讨论
- 目标：明确公开信息流二级标签栏的产品范围与交互规则
- 本文依据：当前对话中已确认的产品意图，以及当前项目源码的实际能力
- 非依据：项目内其他历史设计文档

## 2. 需求背景

公开首页已经通过侧边栏或移动端底部栏划分为“生活、文章、兴趣”三个一级频道，默认进入“生活”，一级频道不提供跨频道的“全部”入口。

一级频道解决了内容大类混合的问题，但随着记录增加，同一频道内部仍会包含差异明显的主题。例如：

- 生活：日常、聚会、旅行、城市见闻
- 文章：学习、工作、AI、读书笔记
- 兴趣：游戏、摄影、赛事、设备体验

访客进入某个频道后，仍需要继续向下浏览才能找到自己关心的主题。需要在信息流滚动区域上方加入频道内标签栏，让三个一级频道都能继续细分。

## 3. 当前实现事实

以下内容是从当前源码确认的行为：

- 一级频道固定为 `life`、`article`、`interest`。
- 公开信息流接口已支持同时使用频道和标签筛选。
- URL 已支持 `channel` 与 `tag` 查询参数，可以直接访问某频道下的某个标签。
- 内容卡片和详情中的标签已经可以点击，并进入对应频道的标签筛选结果。
- 普通记录从正文中的标签生成 `tags`，文章在发布时维护自己的标签，最终统一进入同一标签字段。
- 当前标签查询使用包含关系，不是完整标签的精确匹配。
- 当前无标签的三个频道具有独立信息流实例和滚动位置；带标签的公开信息流尚未纳入同等的保留体验。

这些事实说明首版无需建立第二套内容分类系统，但需要增加稳定的标签栏配置、精确筛选语义和切换状态管理。

## 4. 产品目标

### 4.1 主要目标

- 访客进入一级频道后，可以直接切换该频道下的常用主题。
- 标签栏内容稳定、顺序可控，不随某一页加载结果随机变化。
- 标签切换保持信息流浏览的连续感，不出现每次都像首次进入页面一样的体验。
- PC、手机和平板使用同一套分类语义，并适配各自现有布局。
- 复用内容已有标签，避免同时维护“内容标签”和“频道子分类”两套归属关系。

### 4.2 非目标

首版不包含：

- 第三级及更深层级分类。
- 跨一级频道的全站“全部内容”入口。
- 访客自定义标签栏。
- 标签推荐、搜索联想或个性化排序。
- 根据访问量自动调整标签顺序。
- 独立于内容标签的第二套分类字段。

## 5. 核心产品定义

### 5.1 一级频道与二级标签

- “生活、文章、兴趣”继续作为一级频道。
- 每个一级频道拥有独立的二级标签配置。
- 二级标签直接对应内容现有 `tags` 中的完整标签值。
- 一条内容可以拥有多个标签，因此可以同时出现在同一频道的多个标签页中。
- 内容仍只能归属于一个一级频道。

关系示例：

```text
生活
├── 全部
├── 日常
├── 聚会
└── 旅行

文章
├── 全部
├── 学习
├── 工作
└── AI

兴趣
├── 全部
├── 游戏
├── 摄影
└── 赛事
```

### 5.2 “全部”的范围

标签栏中的“全部”只表示当前一级频道内不按标签筛选：

- 生活 / 全部：所有公开的生活内容
- 文章 / 全部：所有公开文章
- 兴趣 / 全部：所有公开的兴趣内容

它不是被取消的全站一级“全部”入口，也不会混合三个频道。

### 5.3 标签来源

首版建议采用“人工编排展示标签，内容继续使用现有标签”的方式：

- 站点设置页为生活、文章、兴趣分别维护一组展示标签。
- 展示顺序以设置中保存的顺序为准。
- 标签栏不会自动收集并展示所有内容标签。
- 新增展示标签不会修改任何内容；只有本身带有该标签的内容才会进入对应结果。
- 从标签栏删除某个展示标签不会删除内容上的标签，也不会破坏既有带标签链接。

不建议首版直接按公开内容动态生成标签栏。自动聚合会让一次性标签、拼写差异和低频标签进入主导航，并使标签顺序随着内容变化，难以形成稳定的信息架构。

## 6. 访客端交互

### 6.1 默认状态

- 首次访问 `/` 默认进入“生活 / 全部”。
- 进入任一一级频道时，默认选中该频道的“全部”。
- 当前频道没有配置展示标签时，不渲染只有“全部”一个选项的空标签栏。
- 删除公开信息流顶部现有的 `PUBLIC NOTES` 文案，标签栏直接占用它所在的位置，不在 Header 下方额外增加一行。

### 6.2 切换标签

- 点击标签后，只更新当前频道内的信息流。
- 当前选中标签需要有与现有站点一致的红色激活样式。
- 再次点击已经激活的标签不产生新的请求或路由记录。
- 点击“全部”清除当前 URL 中的 `tag` 参数，保留当前频道。
- 标签切换需要进入浏览器历史，前进和后退可以恢复之前的频道与标签。
- URL 继续使用现有语义，例如 `/?channel=article&tag=AI`。

### 6.3 从内容标签进入

卡片或详情中的任意内容标签仍然可以点击，即使它没有被配置为标签栏中的常驻标签。

当访问一个未被编排的标签时：

- 标签筛选继续正常生效。
- 标签栏在常驻标签末尾临时展示该标签，并将其设为激活状态。
- 离开该标签后，临时标签不保留到标签栏配置中。
- 站点设置不因此发生变化。

这样既保持标签栏稳定，又不破坏现有任意内容标签的可访问性。

### 6.4 标签匹配

- 标签栏筛选必须使用完整标签精确匹配。
- `AI` 只匹配标签值为 `AI` 的内容，不能命中仅仅包含该字符串的其他标签。
- 标签文本大小写是否区分，沿用内容发布时已有的标签存储结果，首版不额外合并不同写法。

### 6.5 加载、空状态与结束状态

- 切换到未访问过的标签时，使用与当前信息流形态一致的骨架屏。
- 标签下没有内容时，显示“这个标签下还没有公开内容”。
- 文章频道加载到底时继续显示“已经看到全部文章”。
- 生活和兴趣频道加载到底时继续显示“已经看到全部记录”。
- 标签配置读取失败应直接显示现有统一消息提示，不在界面中展示伪造的默认标签。

## 7. 浏览连续性

### 7.1 频道与标签状态

以下组合应被视为独立的信息流视图：

```text
一级频道 + 当前标签
```

例如“生活 / 旅行”和“生活 / 聚会”分别保留自己的：

- 已加载内容
- 下一页游标
- 当前滚动位置
- 加载完成状态

### 7.2 返回体验

- 从一个标签切换到另一个标签，再切回时，恢复离开前的位置，不重新从顶部开始。
- 从信息流打开详情再返回时，恢复原频道、原标签和原滚动位置。
- 刷新浏览器后以 URL 为准恢复频道和标签；不要求恢复刷新前的内存列表和滚动位置。
- 下拉刷新只刷新当前频道和当前标签，不影响其他已访问标签的内容。

## 8. 布局与响应式规则

### 8.1 PC

- 左侧一级频道侧边栏继续固定展示。
- 标签栏直接替换右侧信息流当前 `PUBLIC NOTES` 所在区域，不横跨左侧侧边栏。
- PC 端原有刷新按钮继续位于该行右侧，标签栏占据左侧可用空间。
- 标签栏在信息流滚动时保持可见。
- 标签数量超出可用宽度时横向滚动，不换行，不压缩成多排。

### 8.2 手机和平板

- 一级频道继续使用底部操作栏。
- 标签栏同样直接替换当前 `PUBLIC NOTES` 所在区域，并在内容滚动时保持可见。
- 移动端不恢复已经移除的独立刷新按钮，下拉刷新继续承担刷新操作。
- 标签栏单行横向滚动，隐藏横向滚动条。
- 切换标签后，激活项需要自动处于可见区域。
- 当前自动隐藏 Header 的交互保持不变；Header 收起后，标签栏仍作为当前频道和筛选状态的轻量锚点保留。
- 标签栏不得遮挡下拉刷新反馈或底部频道栏。

## 9. 站点设置交互

在现有站点设置页增加“频道标签栏”区域，按生活、文章、兴趣分组。

每个频道支持：

- 添加一个标签。
- 删除一个展示标签。
- 调整展示顺序。
- 保存后更新公开页面的标签栏。
- 最多配置 8 个常驻标签；加上固定的“全部”，常规状态最多展示 9 项。

设置行为遵循以下规则：

- 输入的是内容标签原文，不额外添加 `#`。
- 单个标签最多 32 个字符。
- 同一频道内不允许重复标签。
- 不强制三个频道使用相同标签。
- 不要求某个标签已经存在于内容中，可以先配置再发布对应内容。
- 删除展示标签前不增加确认弹窗，因为该操作不会删除内容或标签数据。
- “全部”为系统固定项，不出现在可编辑列表中，也不能删除或改名。

首版设置交互应保持个人项目的短路径，不增加独立的分类管理后台。

## 10. 数据与接口要求

### 10.1 标签栏配置

公开资料需要包含三个频道各自的有序展示标签，概念结构如下：

```json
{
  "channelTags": {
    "life": ["日常", "聚会", "旅行"],
    "article": ["学习", "工作", "AI"],
    "interest": ["游戏", "摄影", "赛事"]
  }
}
```

配置与头像、Bio 一样属于站点公开静态内容：

- 访客可读取。
- 只有已登录的站点所有者可以修改。
- 保存头像或 Bio 时必须保留未修改的频道标签配置。
- 保存频道标签时必须保留未修改的头像和 Bio。

### 10.2 信息流查询

- 继续复用现有公开信息流接口的 `channel` 与 `tag` 参数。
- 标签筛选由当前包含匹配调整为完整值匹配。
- 分页游标继续限定在当前频道与当前标签结果内。
- 不新增一个专门保存“内容属于哪个标签页”的字段。

## 11. 可访问性与操作反馈

- 标签栏使用具有明确名称的导航区域。
- 每个标签项使用可聚焦按钮。
- 激活标签同时提供视觉状态和 `aria-current`，不能只依赖颜色。
- 横向滚动不阻止触摸设备正常纵向滚动信息流。
- 设置页保存成功和失败继续使用项目现有统一消息能力。
- 标签切换本身不弹出消息，激活状态和内容变化已经构成充分反馈。

## 12. 首版范围

首版应完整包含：

- 三个一级频道各自的标签栏。
- 当前频道内“全部”与配置标签切换。
- 设置页标签添加、删除、排序和保存。
- URL、浏览器历史和直接链接支持。
- 精确标签筛选。
- 未配置内容标签的临时激活项。
- PC、手机和平板布局。
- 标签维度的信息流与滚动位置保留。
- 空状态、骨架屏和分页结束文案适配。

## 13. 验收场景

### 13.1 基础导航

1. 打开 `/`，展示生活频道未筛选的信息流。
2. 页面不再展示 `PUBLIC NOTES`，生活频道已配置标签时由同一位置的标签栏选中“全部”。
3. 点击“旅行”，URL 带有 `tag=旅行`，且只展示生活频道中完整标签为“旅行”的公开内容。
4. 点击“全部”，清除标签筛选但仍停留在生活频道。

### 13.2 频道隔离

1. 在生活频道选择“旅行”。
2. 切换到文章频道，文章频道显示自己的标签栏并默认选中“全部”。
3. 文章标签栏不出现生活频道配置的标签。
4. 返回生活频道后恢复“旅行”的列表与滚动位置。

### 13.3 非常驻标签

1. 点击卡片中未配置为常驻标签的 `#深圳`。
2. 信息流按“深圳”精确筛选。
3. 标签栏末尾出现临时的“深圳”激活项。
4. 切换到常驻标签后，临时项消失。

### 13.4 设置管理

1. 在设置页为兴趣频道添加“摄影”。
2. 调整它在兴趣标签栏中的顺序并保存。
3. 公开页兴趣频道按保存顺序展示标签。
4. 删除“摄影”后公开标签栏不再展示它，但原内容上的 `#摄影` 仍存在且仍可从内容标签进入。

### 13.5 移动端与平板

1. 底部栏切换一级频道，顶部标签栏随频道切换。
2. 标签过多时可以横向滑动，页面不产生横向溢出。
3. 上滑内容收起 Header 后，标签栏仍然可见。
4. 下滑恢复 Header 时，标签栏和信息流不发生跳位。

## 14. 建议确认的讨论项

### 14.1 标签栏是否由设置页人工编排

本稿建议人工编排，只复用现有内容标签作为筛选依据。这样比自动展示全部标签更稳定，也更符合标签栏作为长期导航的定位。

### 14.2 标签栏是否始终固定

本稿建议在信息流滚动期间保持可见，尤其在移动端 Header 自动收起后，标签栏可以继续说明当前主题并允许快速切换。

### 14.3 是否保留非常驻标签入口

本稿建议保留现有任意内容标签的点击能力，并以临时激活项承载，避免为了主导航整洁而削弱已有内容探索能力。

### 14.4 切回标签时是否恢复原位置

本稿建议恢复。频道和标签切换都属于同级浏览，不应让访客每次返回都重新加载并回到顶部。
