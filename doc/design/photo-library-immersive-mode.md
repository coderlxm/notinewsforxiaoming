# 照片墙沉浸模式实施方案

## 1. 方案结论

照片墙采用由路由自动驱动的“伪全屏”模式：进入 `/photos` 或 `/photos/:albumId` 后，隐藏顶部 Header，主内容扩展到完整视口，桌面端左侧导航收为边缘指示器；用户靠近或聚焦指示器时，导航以浮层形式临时展开。用户从浮层进入生活、文章、关于我等非照片页面后，应用恢复原有 Header 和固定侧栏，视为退出沉浸模式。

这里的“Netflix 式呈现”指极黑低干扰画布、克制的大画幅焦点展板、全宽内容、高密度横向照片带和密集封面墙，不复制 Netflix 的品牌元素，也不改变照片墙现有的数据来源和照片代理链路。

本轮实施范围只涉及应用壳和照片墙前端呈现，不修改 Google Drive 目录规则、照片索引接口、图片格式、媒体代理、Lightbox 或相册发现逻辑。

## 2. 当前实现依据

当前代码已经具备清晰的改造边界：

- `web/src/App.vue` 统一渲染 Header、公开频道侧栏和路由视口，是切换沉浸壳层的唯一入口。
- `web/src/composables/useAppRoute.ts` 已能从当前路由派生照片墙与相册详情状态，无需建立额外的全局状态。
- `web/src/components/journal/PublicChannelNavigation.vue` 同时承载生活、文章、照片墙和关于我入口，可以在保留导航内容的前提下增加沉浸展示形态。
- `PhotoLibraryView.vue` 负责照片墙首页，当前包含近期精选和相册列表。
- `PhotoAlbumView.vue` 与 `PhotoJustifiedGallery.vue` 负责相册详情，现有 `@egjs/grid` 1.18.x 支持通过 `gap`、`columnRange` 和 `sizeRange` 调整照片密度。
- 当前概览接口已返回 12 张近期精选和每个相册的一张封面；本方案不增加接口字段，也不为了视觉密度额外请求整本相册。
- 当前第一张精选照片就是服务端按拍摄时间等既有规则排出的最新精选，可以直接作为 Hero，不需要新增“主打照片”配置。

## 3. 模式边界

### 3.1 进入条件

下列路由自动进入沉浸模式：

- `/photos`
- `/photos/:albumId`

相册详情仍属于照片墙体验，因此从照片墙进入相册、从相册返回照片墙，都不退出沉浸模式。

### 3.2 退出条件

用户从临时展开的导航进入任一非照片路由后自动退出，包括：

- 生活、文章等公开频道
- 关于我
- 公开记录详情及其他公开页面
- 我的资产等私有页面

退出完全由目标路由决定，不额外维护“是否退出”的布尔状态。浏览器前进或后退回到照片路由时，也会自然恢复沉浸模式。

### 3.3 不设置手动全屏开关

本方案不调用浏览器 Fullscreen API，也不增加“固定全屏”“记住选择”或本地存储。照片路由就是沉浸模式的唯一事实来源，避免 Header、侧栏和页面状态彼此失步。

## 4. 桌面端交互设计

### 4.1 应用壳

进入照片路由后：

- Header 不渲染，原本的顶部栅格行随之消失。
- `.app-shell` 改为单行 `minmax(0, 1fr)`，照片内容占满 `100dvh`。
- `.app-main` 取消 `--workspace-width`、左右 workspace gutter、180px 侧栏列和列间距限制，改为单列全宽布局。
- 路由滚动仍由现有 `.app-scroll` 承担，Lightbox 和滚动容器关系不变。
- 照片区域使用独立的深色影院画布，正文、次要文字、边框和浮层使用照片模式专属 CSS 变量，避免污染全站主题变量。

建议视觉变量：

```css
--photo-canvas: #0c0c0c;
--photo-surface: #171717;
--photo-surface-hover: #222222;
--photo-text-primary: #ffffff;
--photo-text-secondary: rgb(255 255 255 / 70%);
--photo-text-muted: rgb(255 255 255 / 45%);
--photo-glass-bg: rgb(20 20 20 / 75%);
--photo-border: rgb(255 255 255 / 8%);
--photo-gap: clamp(0.5rem, 0.8vw, 0.8rem);
--photo-edge: clamp(1rem, 2.2vw, 2.5rem);
```

### 4.2 左侧边缘指示器

收起时只保留一个靠左、垂直居中的悬浮指示器：

- 可视尺寸约 `40 × 72px`，点击热区不小于 `44 × 72px`。
- 使用向右的双线箭头或“导航轨道”图形，不使用汉堡菜单，避免让用户误解为传统抽屉菜单。
- 采用半透明深色背景、细边框和轻微阴影；默认低对比，hover 或键盘聚焦时提高亮度。
- 指示器不遮挡照片主体，仅覆盖视口最左侧小范围。

指示器是实际 `<button>`，提供“展开页面导航”的可访问名称，并同步 `aria-expanded`。

### 4.3 临时侧栏

下列行为均可展开临时侧栏：

- 鼠标进入边缘指示器。
- 指示器获得键盘焦点。
- 点击指示器。

展开后的导航：

- 从视口左侧覆盖式滑入，宽度约 `220px`，不挤压或重新计算照片墙宽度。
- 高度覆盖完整视口，背景使用 `--photo-glass-bg` 和适量毛玻璃效果，并在右缘增加柔和阴影和渐变。
- 复用当前公开导航的频道顺序、激活态和事件，不复制第二份菜单数据。
- 鼠标离开指示器与侧栏构成的整体区域后收起；键盘焦点仍在侧栏内时保持展开。
- 按 `Escape` 时收起并把焦点交还指示器。
- 不增加延时计时器，开合由明确的 pointer、focus 和 click 状态驱动。

点击行为：

| 点击目标 | 目标路由 | 点击后的壳层状态 |
| --- | --- | --- |
| 照片墙 | `/photos` | 保持沉浸模式，侧栏收起 |
| 生活、文章等频道 | 对应公开频道 | 退出沉浸模式，恢复 Header 和固定侧栏 |
| 关于我 | `/about` | 退出沉浸模式，恢复 Header 和固定侧栏 |
| 我的资产入口 | 对应私有路由 | 退出沉浸模式，恢复正常私有壳层 |

## 5. 移动端与触摸设备

移动端没有可靠 hover，因此不照搬桌面边缘抽屉：

- 照片路由仍隐藏顶部 Header，让照片获得更多垂直空间。
- 保留现有底部公开导航，并继续作为正常文档流中的固定导航区域，不悬浮覆盖照片。
- 照片内容占据底部导航之外的全部可用高度。
- 点击底部的非照片入口后恢复正常 Header；点击照片墙保持沉浸模式。
- 不增加隐藏底部导航的手势或二次开关，避免用户失去可发现的退出入口。

断点沿用当前公共布局边界：`799px` 及以下使用底部导航，`800px` 及以上使用左侧悬浮导航。对不支持 hover 的大屏触摸设备，指示器仍可通过点击展开。

## 6. Netflix 式照片墙首页

### 6.1 克制版 Hero 焦点展板

用第一张近期精选替代当前以文字和留白为主的页面头部，形成进入照片墙后的主视觉：

- Hero 直接使用 `overview.featured[0]`，不增加配置字段或接口。
- 桌面端高度使用 `clamp(22rem, 48vh, 35rem)`，移动端约 `clamp(18rem, 42vh, 26rem)`，不采用占据 65vh 的大型海报。
- Hero 使用实际图片组件和现有 preview 渐进加载，不使用 CSS `background-image`，保留替代文本、加载状态和点击查看能力。
- 主图使用现有 `view` 变体；点击后打开现有 Lightbox 的第 0 张。
- `PHOTOGRAPHY`、`照片墙` 和现有说明叠加在左下安全区域，标题仍保持页面唯一的 `<h1>`。
- 底部使用从透明到 `--photo-canvas` 的纵向渐变，左右增加轻微暗角，使 Hero 与下方照片带无缝衔接。
- 元数据只使用当前已经存在的照片标题、拍摄日期、相机和镜头；不展示当前数据契约中不存在的地点或精选标签。
- 首张精选不再重复进入下方滚动照片带；Hero 与剩余精选共同组成原来的 12 张照片。
- Hero 底部必须露出“近期精选”分区标题或首排照片边缘，避免主图重新制造大面积单图首屏。

Hero 独立为 `PhotoHeroBillboard.vue`，由 `PhotoLibraryView.vue` 传入照片并接收 `open-photo` 事件。`PhotoLibraryView.vue` 用纯 `computed` 派生 Hero 照片与剩余精选，不在模板中反复执行 `slice`。

### 6.2 近期精选

保留现有自动滚动和两端柔和过渡，用 Hero 之外的 11 张精选组成更密集的影院照片带：

- 照片带全宽延伸，不受 1220px 容器限制。
- 左右只保留 `--photo-edge` 安全边距，照片之间的间距由当前 16px 收紧到约 `8–10px`。
- 单张高度控制为 `clamp(11rem, 18vw, 16rem)`，同屏展示更多照片。
- 圆角从当前卡片感较强的尺寸收紧到约 `6px`。
- EXIF 信息继续叠加在照片内部，不另占纵向空间。
- hover 仍只做轻微放大，自动滚动的暂停、键盘聚焦和减少动态效果行为保持不变。
- 点击滚动带照片时，将局部索引映射回完整精选列表后打开 Lightbox，确保 Hero 拆出后浏览顺序不变。

### 6.3 相册封面墙

把当前三列、文字位于图片下方的相册卡片，调整为 Netflix 式高密度封面墙：

- 统一使用 `16:10` 封面比例，封面继续 `object-fit: cover`。
- 相册名称、照片数量和日期放入封面底部渐变层，减少卡片纵向占用。
- 默认显示名称和照片数量；日期作为次要信息在 hover、focus-visible 时增强显示。
- hover 或键盘聚焦时使用约 `scale(1.02–1.03)`、轻微上浮和深色扩散阴影，不使用 `scale(1.06)` 或跨卡片的高层级覆盖。
- 卡片元数据使用普通半透明深色表面，不为每张卡片增加 `backdrop-filter`，避免密集卡片同时建立大量毛玻璃合成层。
- 整个封面仍为一个 `RouterLink`，不在卡片内部增加第二个交互元素。

建议响应式密度：

| 视口宽度 | 相册列数 | 水平间距 |
| --- | ---: | ---: |
| `>= 1440px` | 5 列 | 12px |
| `1100–1439px` | 4 列 | 10px |
| `800–1099px` | 3 列 | 10px |
| `360–799px` | 2 列 | 8px |
| `< 360px` | 1 列 | 8px |

该设计只让现有相册封面更紧凑，不会为了填满首页而提前获取所有相册照片。

相册区域保持可一次纵向浏览的响应式网格，不改成横向滚动泳道，也不增加左右翻页箭头或强制 Scroll Snap。现有近期精选已经承担横向影院泳道的角色，相册墙优先保证密度和可发现性。

## 7. 相册详情密度

相册详情继续使用保持原始比例的 justified gallery，不改为统一裁切卡片：

- 取消 1320px 最大宽度，画廊使用全宽减去 `--photo-edge`。
- 取消占据文档高度的传统详情 Header，让画廊从内容视口顶部直接开始铺设。
- 返回入口、相册标题、照片数量和日期整合为一颗左上角悬浮胶囊工具条；工具条使用 `--photo-glass-bg`、`backdrop-filter: blur(16px)`、细边框和阴影。
- 工具条位于现有 `.app-scroll` 内，以 sticky 覆盖层形式停留在安全边距内，不切割画廊，也不脱离当前路由滚动容器。
- 工具条限制最大宽度，长相册名使用省略显示；移动端同时避开安全区和底部导航。
- `@egjs/grid` 的 `gap` 从 10px 收紧至约 6px。
- `columnRange` 由 `[1, 5]` 放宽为 `[1, 7]`，让大屏最多形成七张一行。
- `sizeRange` 由 `[160, 320]` 收紧为约 `[140, 260]`，提高单位视口内的照片数量。
- 保持 `isCroppedSize: false`，不为了密度破坏照片原始比例。
- 继续使用 preview 渐进占位和 card 图，图片点击后进入现有 Lightbox。

画廊密度调整依赖现有 Grid 的 ResizeObserver 自动重排，不额外监听窗口尺寸，也不引入新的布局库。悬浮工具条独立为 `PhotoAlbumFloatingToolbar.vue`，只接收相册名称、数量和日期，由 `PhotoAlbumView.vue` 保持数据编排职责。

## 8. 状态与组件设计

### 8.1 单一状态来源

在 `App.vue` 中从现有 `photosActive` 派生：

```ts
const photoImmersiveActive = computed(() => photosActive.value);
```

该值只负责壳层形态：

- Header 是否渲染。
- App Shell 是否使用单行全宽布局。
- 公开导航使用固定形态还是沉浸形态。
- 路由视口是否使用照片影院背景。

临时侧栏开合是 `PublicChannelNavigation.vue` 的局部交互状态，不进入 Pinia，也不写入 URL 或本地存储。

### 8.2 组件职责

| 文件 | 单一职责与改动 |
| --- | --- |
| `web/src/App.vue` | 根据照片路由派生沉浸壳层；控制 Header、主栅格和导航展示形态 |
| `web/src/composables/useAppRoute.ts` | 保持路由解析职责；可直接复用现有照片路由判断，不新增独立状态 |
| `web/src/components/journal/PublicChannelNavigation.vue` | 在同一份导航内容上支持 `fixed` 与 `photo-immersive` 两种展示模式；管理临时展开、焦点和 Escape |
| `web/src/components/photos/PhotoLibraryView.vue` | 编排 Hero、剩余精选、Lightbox 索引和全宽相册分区 |
| `web/src/components/photos/PhotoHeroBillboard.vue` | 呈现第一张精选 Hero、标题、现有元数据和渐变氛围，并向上发出打开照片事件 |
| `web/src/components/photos/FeaturedPhotoStrip.vue` | 调整照片带尺寸、间距、圆角和两端渐变范围 |
| `web/src/components/photos/PhotoAlbumGrid.vue` | 实现高密度响应式封面列数 |
| `web/src/components/photos/PhotoAlbumCard.vue` | 将相册信息移动到封面渐变层，并保留单一链接语义 |
| `web/src/components/photos/PhotoAlbumView.vue` | 编排相册数据、悬浮工具条和全宽画廊 |
| `web/src/components/photos/PhotoAlbumFloatingToolbar.vue` | 呈现返回入口、相册标题、数量和日期，不拥有相册数据状态 |
| `web/src/components/photos/PhotoJustifiedGallery.vue` | 调整现有 Grid 参数以提高照片密度 |

不新建全局 store，不新增应用级 provide/inject，也不把照片模式写入通用主题控制。

### 8.3 组件数据流

`App.vue` 通过只读 prop 将导航模式传给 `PublicChannelNavigation.vue`。导航仍通过现有 `select`、`select-about`、`select-photos` 事件向上通知，路由跳转继续由 `App.vue` 执行。

`PhotoLibraryView.vue` 将完整精选列表分别作为 Hero 照片和剩余照片向下传递。Hero 和滚动带都只向上发出照片索引或打开事件，由页面统一调用 Lightbox，不让展示组件直接访问 Pinia。

`PhotoAlbumView.vue` 将格式化后的标题、数量和日期作为只读 prop 传给悬浮工具条；工具条内部只包含返回照片墙的路由链接，不反向修改父组件状态。

临时侧栏只维护一个局部 `shallowRef<boolean>`：

- pointer enter、focus 或 click 将其打开。
- pointer leave、focus 离开整体区域或 Escape 将其关闭。
- 导航事件触发时先关闭局部侧栏，再由父组件执行路由跳转。

不使用 `watch` 同步路由和开合状态；离开照片路由后组件展示模式自然回到固定形态。

## 9. 动效与可访问性

- 侧栏滑入只使用 `transform` 与 `opacity`，建议时长 `180–220ms`。
- 不使用 `requestAnimationFrame`，也不增加基于计时器的延迟开关。
- Hero 渐变和暗角保持静态，不对背景执行持续缩放、自动切换或视差动画。
- 在 `prefers-reduced-motion: reduce` 下取消侧栏位移、卡片上浮和图片放大，仅保留立即显示与隐藏；现有精选自动滚动继续遵循已有静态模式。
- 边缘指示器必须可 Tab 聚焦；展开后导航顺序与视觉顺序一致。
- 临时侧栏不是模态框，不锁定页面滚动，不设置遮挡全屏的透明 backdrop。
- 侧栏展开时不隐藏其余页面的可访问树；用户仍可滚动照片，导航只是覆盖左侧局部区域。
- 所有照片和相册继续使用现有替代文本、按钮或链接语义。

## 10. 性能边界

本方案通过布局提高视觉密度，但不提高首页媒体请求总量：

- 精选仍为现有 12 张，其中第一张作为 Hero，剩余 11 张进入自动滚动照片带，不在首屏重复请求同一张照片的卡片版本。
- 相册列表仍只展示每个相册的一张封面。
- 不在首页批量调用相册详情接口。
- Hero 使用 preview 到 view 的渐进加载并作为首屏 eager 图片；照片带和非首屏图片继续使用原有 lazy loading。
- 不引入视频背景、Canvas、WebGL 或额外轮播库。
- 毛玻璃只用于单个相册工具条和临时导航等少量浮层，不应用到每一张相册卡片。
- 相册详情继续复用 Pinia 中已经加载的相册状态和现有不可变媒体 URL。

因此，主要变化是同一批图片在更大的内容区域中排列得更紧凑，而不是让宿主机同时转换更多种图片资源。

## 11. 实施顺序

1. 在应用壳加入由照片路由派生的沉浸模式，先完成 Header 隐藏和全宽单列布局。
2. 为公开导航增加沉浸展示形态，完成边缘指示器、hover、点击、键盘焦点和退出行为。
3. 建立照片模式的极黑色阶和全宽画布，并新增克制版 Hero 焦点展板。
4. 将首张精选从滚动带中拆出，调整剩余精选的索引映射、尺寸、间距和渐变，保留当前自动滚动及 EXIF 行为。

## 12. 完成标准

- 从任意页面进入照片墙后，Header 消失，照片区域占满除移动端底部导航以外的完整视口。
- 桌面端收起状态只显示左侧边缘指示器，照片内容不为隐藏侧栏预留空白列。
- hover、点击和键盘聚焦都能展开同一份导航，展开过程不引起照片墙横向重排。
- 点击照片墙或在照片墙与相册详情之间切换时保持沉浸模式。
- 点击生活、文章、关于我等非照片入口后恢复 Header 和固定侧栏。
- 浏览器前进、后退和直接访问照片路由时，壳层状态始终与当前路由一致。
- 大屏照片墙首屏显示克制高度的 Hero，同时露出近期精选标题或照片边缘；Hero 只使用现有元数据。
- Hero 使用第一张精选，滚动带从第二张开始，Lightbox 中仍保持完整 12 张的原有顺序。
- 相册墙在 1440px 以上展示五列，卡片 hover 不遮挡相邻卡片，也不为每张卡片创建毛玻璃层。
- 相册详情从视口顶部开始铺图，左上角悬浮工具条不占据画廊纵向空间；大屏最多形成七张一行并保持原始照片比例。
- 移动端无需 hover 即可通过底部导航退出照片墙，照片内容不被浮层菜单长期遮挡。
- 减少动态效果开启时，不出现持续滚动、侧栏滑动、卡片上浮或图片缩放。
