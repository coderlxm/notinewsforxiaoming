# Web 内容主题（Topic）功能方案

## 1. 需求结论

在“发布内容 / 编辑记录”中增加一个可选的“主题”输入框，使 Web 发布的普通记录形成“主题 + 正文”的内容结构。

对外信息流中，纯文字记录的画报展示遵循：

```text
有主题：画报展示主题
无主题：画报展示去除标签后的正文
```

画报下方的摘要继续展示正文，并沿用当前两行截断规则。这样主题负责快速表达内容主旨，摘要负责补充正文开头，不会在卡片中重复展示同一段主题。

## 2. 改动量评估

结论：**中等改动，不是单个输入框级别，但不需要新增业务表或重做卡片系统。**

预计涉及约 10 个现有文件，覆盖以下四层：

1. 数据约束与迁移：普通 Web 记录当前被数据库约束为 `title IS NULL`，需要新增一次数据库迁移，允许普通记录保存可选主题。
2. 服务端写入链路：创建、保存草稿、草稿发布、编辑已发布记录都要接收并保存主题。
3. 管理端发布链路：主题输入、编辑回填、草稿保存、发布和再次编辑都要保持同一状态。
4. 公开呈现：纯文字画报改为主题优先，详情页展示主题与正文，搜索文案与已有标题搜索能力对齐。

当前模型已经有 `JournalEntry.title` 字段，管理表格、搜索和 RSS/JSON Feed 也已经存在标题优先逻辑，因此可以复用现有字段，不需要再增加一套 `topic` 数据模型。这显著缩小了实现范围。

## 3. 产品定义

### 3.1 主题输入

- 发布器正文区域顶部增加单行“主题（选填）”输入框。
- 最多 60 个字符；主题定位为一句简短主旨，不承载长正文。
- 输入首尾空白在提交时去除。
- 空字符串统一保存为 `null`，不保留无意义空标题。
- 正文或媒体仍是发布和保存草稿的有效内容条件；只有主题、没有正文和媒体时不可保存或发布。
- 主题不解析 `#标签`，标签仍只从正文中提取。

### 3.2 适用范围

- 新建 Web 普通记录可以设置主题。
- 已有 Web 普通记录可以在编辑页新增、修改或清空主题。
- 已有旧记录保持无主题状态，继续使用正文兜底，不做数据回填。
- Telegram 采集记录不增加主题编辑入口；其内容归属现有采集链路，继续以正文作为画报文本。
- 文章继续使用现有文章标题能力，不改变文章编辑器和文章卡片。

### 3.3 管理端呈现

- 发布器按“主题 → 正文 → 媒体”的顺序组织内容输入。
- 编辑 Web 记录时，主题与正文一起回填，避免只回填正文导致主题被意外清空。
- 管理表格已经具备“标题为主文本、正文为次文本”的结构，主题落入现有 `title` 后即可自然呈现，不新增表格列。
- 管理筛选后端已经同时匹配 `title` 和 `content_text`；将筛选输入文案由“正文关键词”改为“主题或正文”，使界面描述与真实行为一致。

### 3.4 公开信息流卡片

- 仅对当前会生成画报的纯文字普通记录应用主题优先规则。
- 画报文本为 `trim(title) || stripTags(contentText)`。
- 画报的短、中、长文本密度和自适应高度，以最终选中的画报文本重新计算。
- 主题过长时继续使用现有画报截断和密度控制，不新增第八套模板，也不为主题建立另一套视觉系统。
- 画报下方摘要仍展示正文，两行后省略；不展示标签。
- 带图片或视频的卡片继续以媒体为视觉主体，不额外生成画报。其详情页仍会展示主题与正文。

### 3.5 详情、加密与订阅

- 普通记录详情中，有主题时先展示主题标题，再展示正文；无主题时保持当前正文布局。
- 加密内容锁定时仍只显示脱敏预告，不把主题加入预告结构，避免主题泄露私人内容。
- 管理员查看或访客解锁后，返回完整记录并正常展示主题。
- 公开记录进入 RSS/JSON Feed 时，复用现有标题优先规则：主题作为条目标题，正文作为描述和内容。
- 私有与加密内容继续不进入 RSS/JSON Feed，现有可见性规则不变。

## 4. 数据与接口方案

### 4.1 字段复用

产品名称使用“主题”，技术模型继续使用现有 `title: string | null`：

```text
普通记录 title = 主题或 null
文章 title = 文章标题
```

两者通过现有 `bodyFormat` 区分，不增加 `topic` 与 `title` 两个含义重叠的字段。

### 4.2 数据库迁移

新增下一版本迁移，重建 `journal_entries` 的类型约束：

- Web 富文本文章继续要求标题非空。
- Web 普通记录由“标题必须为空”调整为“标题可为空；非空时必须是去除首尾空白后的有效主题”。
- 原数据原样复制，旧记录的 `title = null` 不变。
- 其他发布状态、加密密码、频道、媒体和来源约束保持不变。

SQLite 的现有规则写在表级 `CHECK` 中，不能通过简单 `ALTER COLUMN` 修改，因此数据库迁移是这项需求不可省略的改动。

### 4.3 请求契约

普通 Web 记录的以下请求统一增加 `title: string | null`：

- 新建草稿
- 直接发布
- 更新草稿
- 草稿转发布
- 更新已发布 Web 记录

服务端统一校验 60 字符上限并持久化。`JournalEntry` 响应结构无需变化，因为当前已经包含可空 `title`。

## 5. 前端组件与状态流

### 5.1 发布器

在 `EntryPublisherView` 中增加一个主题状态，并遵循现有单向数据流：

```text
加载记录
  → entry.title 回填主题输入
  → buildInput 同时提交 title 与 contentText
  → 保存结果回写 title 与 contentText
```

主题输入使用独立的小组件承载标签、字数限制和输入样式；发布器继续持有业务状态和提交行为，不让输入组件直接调用 API。

### 5.2 画报

`JournalTextPoster` 只负责从记录中计算最终画报文本：

```text
entry.title?.trim() || stripJournalTags(entry.contentText, entry.tags)
```

`EntryCard` 的画报存在条件继续由普通文本、无媒体和可展示文本共同决定。摘要仍从正文生成，不被主题替换。

### 5.3 详情

普通记录详情补充主题标题节点；文章详情保持原结构。主题只影响内容呈现，不改变打开详情、编辑、权限和媒体加载流程。

## 6. 主要文件范围

预计直接修改：

- `src/shared/journalProtocol.ts`：普通 Web 记录请求增加可空标题及长度规则。
- `src/journal-server/migrations.ts`：放宽普通 Web 记录的标题约束。
- `src/journal-server/repository.ts`：创建、草稿、发布、已发布编辑写入标题。
- `src/journal-server/webEntryService.ts`：主题沿完整 Web 记录主路径传递。
- `src/journal-server/routes/privateEntries.ts`：草稿更新字段映射补齐标题。
- `web/src/api.ts`：发布与更新请求携带标题。
- `web/src/composables/useEntryPublisher.ts`：发布器输入契约透传标题。
- `web/src/components/publisher/EntryPublisherView.vue`：主题状态、回填和表单布局。
- `web/src/components/publisher/EntryTopicField.vue`：单行主题输入组件。
- `web/src/components/journal/JournalTextPoster.vue`：画报主题优先。
- `web/src/components/journal/JournalDetailContent.vue`：普通记录详情展示主题。
- `web/src/components/journal/AssetManagementToolbar.vue`、`EntryFilters.vue`：搜索文案改为“主题或正文”。

现有管理表格、公开 Feed 输出和 `JournalEntry` 返回类型无需增加新结构，只需要确认继续复用已有 `title` 行为。

## 7. 不在本次范围内

- 不给 Telegram 采集记录增加主题编辑能力。
- 不改变文章标题及文章编辑器。
- 不新增主题筛选器、主题聚合页或主题标签体系。
- 不把主题当作标签，也不自动由正文生成主题。
- 不改变媒体卡片的主体布局。
- 不在加密预告卡片中泄露主题。

## 8. 完整主路径

### 8.1 新建并发布

1. 进入发布内容页。
2. 可选填写主题，填写正文或添加媒体。
3. 保存草稿或直接发布。
4. 再次进入编辑页时主题与正文完整回填。
5. 对外纯文字画报展示主题，卡片摘要展示正文。

### 8.2 无主题兼容

1. 新建内容时不填写主题，或编辑旧记录。
2. 保存后 `title` 为 `null`。
3. 纯文字画报继续展示去标签后的正文。
4. 管理表格、详情和 RSS/JSON Feed 保持当前正文兜底行为。

### 8.3 清空主题

1. 编辑一条已有主题的 Web 记录。
2. 清空主题并保存。
3. 数据恢复为 `title = null`。
4. 公开画报立即恢复正文兜底，不残留旧主题。

### 8.4 加密内容

1. 发布带主题的加密记录。
2. 未解锁访问只看到统一加密预告，不看到主题和正文。
3. 管理员或正确解锁后看到主题、正文和媒体的完整内容。

## 9. 验收标准

- 发布页和 Web 记录编辑页均有可选主题输入，且不会挤压现有发布设置区域。
- 主题可以随草稿保存、发布、再次编辑和清空完整持久化。
- 普通记录仍必须包含正文或媒体，主题不能单独构成一条记录。
- 有主题的纯文字公开卡片，画报只展示主题；卡片摘要展示正文。
- 无主题记录的画报和旧数据呈现与当前一致。
- 普通记录详情按“主题 + 正文”呈现；文章详情不受影响。
- 管理搜索可以通过主题或正文命中，界面文案与行为一致。
- 带主题的加密记录在未解锁状态不泄露主题。
- 公开 RSS/JSON Feed 使用主题作为条目标题；无主题时继续使用正文摘要。

## 10. 推荐决策汇总

- 主题可选，最多 60 个字符。
- 复用现有 `title` 字段，不新增 `topic` 字段。
- 主题不参与标签解析，正文/媒体仍决定内容是否有效。
- 纯文字画报主题优先，卡片底部摘要保持正文。
- 搜索覆盖主题与正文，并同步调整搜索提示文案。
- 普通详情展示主题；加密预告不展示主题。
- 首版只开放给 Web 发布的普通记录，Telegram 记录维持正文模式。
