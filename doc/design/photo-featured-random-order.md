# 照片墙近期精选随机排序方案

## 需求理解

希望照片墙的“近期精选”滚动照片在首次进入和浏览器刷新后换一种排列，减少第一眼总是看到相同照片的视觉重复。照片仍来自近期精选范围；站内离开再返回时复用缓存顺序。

用户已认可保留现有选片范围、仅改变滚动条展示顺序的方案，并明确随机顺序只在首次进入和浏览器刷新后更新。

## 当前源码事实

- `src/journal-server/photoLibraryService.ts`：精选候选先按设备、横竖幅分层，同层内按拍摄时间倒序，最后取前 12 张。因此当前没有“最近多少天”的时间窗口，也不是全库严格按时间取最新 12 张。
- `web/src/components/photos/PhotoLibraryView.vue`：滚动条使用 `featured.slice(1)`，最多展示 11 张，顺序固定；顶部大图也使用精选数据。
- 滚动条通过数组索引通知父组件，父组件用 `index + 1` 打开原始精选列表中的照片。直接打乱滚动条后，必须同步调整该对应关系。
- 概览数据保存在 store 中，可以复用；照片墙路由组件当前没有放入 KeepAlive。

以上是本地源码行为，不据此推定线上照片的实际日期分布。

## 拟采用的行为

1. 保留现有精选选片规则和滚动条照片集合，先确定候选照片，再随机排列。
2. 当前浏览器页面首次进入照片墙时生成一次随机顺序，并随概览数据保存在内存缓存中。浏览器刷新后缓存重建，再生成一次随机顺序。
3. 站内离开照片墙后返回、相册返回、图片加载、悬停暂停、继续滚动、打开大图和关闭大图均复用缓存顺序，不重新洗牌。
4. 无缝滚动的两组照片使用同一个随机结果，保持首尾衔接。
5. 点击任意照片仍打开该照片；大图查看器继续沿用现有精选列表的前后翻阅顺序，通过照片 ID 对应原列表位置。
6. 随机排列允许偶然出现相同首图或相同排列，不增加跨次历史记录或强制去重规则。

## 最小修改范围

预计修改两个文件：

- `web/src/stores/photoLibrary.ts`：随首次概览加载生成滚动条的随机副本，并在现有 store 中保留。路由组件销毁不清除该顺序，返回时直接复用；浏览器刷新后随 store 重建。无需增加持久化存储或路由缓存机制。
- `web/src/components/photos/PhotoLibraryView.vue`：读取 store 中缓存的滚动条顺序，同时将点击位置转换为照片 ID，再定位到大图列表。

随机排列优先复用项目已声明的成熟工具库能力，实施前核对安装版本、公开 API 与本地解析情况。保留概览中原始精选数组的顺序，只对滚动条副本随机排列，不让组件重建、渲染或动画事件触发随机排列。

`FeaturedPhotoStrip.vue` 继续负责展示、循环滚动和点击事件，预计无需修改。顶部大图、相册排序、服务端接口和精选生成规则不在本轮修改范围内。

## 审阅重点

本方案把“近期的前提下”理解为沿用目前的精选来源。如果用户希望改成严格按拍摄时间选最近一批，或限定最近若干天，那属于选片规则调整，需要先明确时间范围，再确定服务端修改范围。

当前仅更新方案，尚未修改业务代码。
