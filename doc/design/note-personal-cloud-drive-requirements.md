# `/note` 个人网盘记录功能需求

## 1. 目标

在 Telegram bot 中增加 `/note` 功能，让用户可以把 Telegram 支持的常见内容保存到个人网盘，作为个人资料、灵感和临时事项的统一记录入口。

首期目标是“发送即保存、结果明确”，不建设复杂的知识库、搜索引擎或多用户权限系统。

## 2. 核心使用方式

### 2.1 命令后直接记录文本

```text
/note 记得研究 start.gg 的赛程接口
```

bot 将文本保存到个人网盘，并回复保存结果。

### 2.2 回复一条 Telegram 消息进行记录

用户回复任意一条消息并发送：

```text
/note
```

bot 保存被回复消息的内容。

被回复消息可以是：

- 文本
- 图片
- 语音
- 音频
- 视频
- 视频消息
- 文档或其他文件
- 动图
- 贴纸
- 联系人
- 地理位置
- 投票
- Telegram 可提供给 bot 的其他消息内容

### 2.3 命令后发送一条内容

用户发送：

```text
/note
```

bot 进入“等待记录内容”状态，并提示用户发送下一条消息。用户随后发送的第一条内容会被保存，保存完成后退出等待状态。

该状态只服务单次记录，不形成持续会话。

### 2.4 媒体附带说明

如果图片、视频、文件等消息带有 caption，文件与 caption 一起保存。

## 3. 保存内容

每条 note 在网盘中保存为一个独立目录：

```text
notes/YYYY/YYYY-MM/YYYY-MM-DD/HHmmss_<message_id>/
```

目录内包含：

```text
note.md
原始附件文件（如有）
```

### 3.1 `note.md`

记录以下信息：

- 记录时间，使用 `Asia/Shanghai`
- Telegram chat id
- Telegram message id
- 消息类型
- 文本或 caption
- 原消息发送时间
- 被回复消息信息（如果通过回复保存）
- 附件原始文件名、MIME type 和保存文件名
- Telegram 中可获得的结构化内容，例如位置、联系人或投票信息

### 3.2 原始附件

媒体和文件保存 Telegram 提供的原始文件，不主动压缩、转码或生成替代格式。

如果一条消息包含多个媒体文件，全部保存在同一 note 目录中。

## 4. Telegram 交互

### 保存成功

```text
✅ Note 已保存
类型：视频
时间：2026-07-11 20:30
文件：example.mp4
```

### 等待内容

```text
请发送要记录的内容。下一条消息将保存为 Note。
```

### 取消等待

等待状态下发送：

```text
/cancel
```

取消本次记录，不保存内容。

### 保存失败

Telegram 文件下载、网盘写入或元数据写入任一步骤失败时，直接回复明确错误。本次 note 不返回成功，不静默跳过附件，也不改用其他存储通道。

## 5. 身份与权限

- 仅允许当前 bot 已授权的 Telegram chat 使用 `/note`。
- 不增加多用户空间、共享链接或公开访问能力。
- 网盘凭据只保存在服务器环境配置中，不写入 note 文件或 Telegram 回复。

## 6. 网盘要求

具体网盘厂商和接入方式待确认。首期接入必须满足：

- 支持创建目录。
- 支持上传文本和二进制文件。
- 支持稳定保存 Telegram 允许下载的文件大小。
- 提供成熟、维护良好的 Node.js SDK 或标准协议客户端。
- 上传失败能够直接返回错误。

优先使用目标网盘官方 SDK；如果网盘以本地挂载目录形式提供，则直接写入明确配置的挂载路径。

## 7. 内容类型处理

| Telegram 内容 | 保存方式 |
| --- | --- |
| 文本 | 写入 `note.md` |
| 图片 | 下载原图文件，caption 写入 `note.md` |
| 语音 | 下载原始语音文件，不转文字 |
| 音频 | 下载原始音频文件并记录歌曲元数据 |
| 视频 | 下载原始视频文件 |
| 视频消息 | 下载原始视频消息文件 |
| 文档 | 保留 Telegram 文件名和 MIME type |
| 动图 | 保存 Telegram 提供的原始文件 |
| 贴纸 | 保存原始贴纸文件并记录 emoji/set 名称 |
| 联系人 | 结构化写入 `note.md` |
| 位置 | 经纬度及可用地点信息写入 `note.md` |
| 投票 | 问题和选项写入 `note.md` |
| 不支持的消息 | 明确报错，不返回保存成功 |

首期不进行 OCR、语音转文字、视频摘要或 AI 分类。

## 8. 文件命名

- 优先使用 Telegram 提供的原始文件名。
- 没有原始文件名时，按内容类型和 Telegram file unique id 生成稳定文件名。
- 同一 note 内文件名冲突时直接报错，不静默覆盖已有文件。
- note 目录使用 Telegram message id 区分，避免同秒记录冲突。

## 9. 一致性要求

一条 note 的成功条件是：

```text
note.md 写入成功
并且
该消息要求保存的全部附件写入成功
```

任一必需内容失败，本次操作整体失败。不得只保存文本却声称附件也已保存。

同一 Telegram message 重复执行 `/note` 时，首期允许创建一条新的 note 记录，不做自动去重。

## 10. 首期不包含

- Note 搜索、标签和分类
- Note 编辑和删除
- 网盘文件反向发送到 Telegram
- OCR、语音识别和内容摘要
- 自动识别“值得保存”的普通消息
- 多条消息批量收集
- 相册媒体组聚合
- 网盘故障时的本地暂存、重试或其他存储 fallback
- 多用户及共享功能

## 11. 待确认事项

实施前需要确认：

1. 目标个人网盘是什么产品。
2. 使用官方 API、WebDAV、S3 兼容接口，还是服务器本地挂载目录。
3. 网盘根目录名称和路径。
4. 是否接受 Telegram bot API 对可下载文件大小的限制。
5. `/note` 空命令等待下一条消息是否需要超时；首期建议由 `/cancel` 显式结束，不自动超时。

## 12. 首期验收标准

- `/note 文本` 能在网盘生成包含正文的 note。
- 回复文本、图片、语音、视频和文档发送 `/note`，能保存对应内容。
- `/note` 后发送下一条消息，能完成单次保存并退出等待状态。
- caption 和 Telegram 元数据正确写入 `note.md`。
- 附件以原始格式保存。
- 未授权 chat 无法使用。
- `/cancel` 可以取消等待状态。
- 任一步骤失败时明确报错，且不返回成功消息。
