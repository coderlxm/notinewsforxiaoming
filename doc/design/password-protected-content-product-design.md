# Web 端加密内容产品方案

## 文档状态

- 阶段：产品方案已确认，首版已实现
- 适用范围：Web 端发布的普通内容与富文本文章，以及已存在的所有记录
- 推荐名称：管理端称“加密”，访问页称“密码保护”

## 1. 背景与问题

当前内容只有两种可见范围：

- 公开：出现在公开信息流、公开详情、RSS 和 JSON Feed 中。
- 私有：仅管理员登录后可在“我的全部记录”中查看。

这两种状态无法覆盖“只分享给知道密码的人”的场景。私人日记、写给特定好友的文章或带有私人图片、视频的记录，既不适合完全公开，也不应该要求访问者拥有管理员账号。

本次需要增加第三种可见范围，让管理员可以给新内容设置访问密码，也可以把已有公开或私有内容改为加密内容，并通过原有详情链接分享给指定好友。

## 2. 产品定义

新增第三种可见范围：`加密`。

| 可见范围 | 公开信息流 | RSS / JSON Feed | 直接链接 | 管理员后台 |
| --- | --- | --- | --- | --- |
| 公开 | 展示 | 展示 | 直接查看 | 展示 |
| 加密 | 展示脱敏预告卡片 | 不展示 | 输入密码后查看 | 直接查看 |
| 私有 | 不展示 | 不展示 | 按不存在处理 | 展示 |

加密内容仍使用现有 `/p/:publicId` 详情链接。它不是另一套内容，也不创建额外分享链接。内容在公开、加密、私有之间切换时，链接保持不变。

### 2.1 “加密”的准确边界

本方案实现的是服务端密码访问控制：正文和媒体文件仍保存在现有服务器中，服务端验证密码后才允许访问。

它不属于端到端加密，也不解决“服务器本身无法读取内容”的需求。真正的端到端或磁盘密文方案会改变文章渲染、图片预览、视频播放、搜索和后台编辑整条主路径，不适合当前个人项目的目标。

## 3. 产品目标

1. 发布普通内容或文章时，可以选择“加密”并设置密码。
2. 已有公开或私有内容，可以直接改为加密内容。
3. 知道链接和密码的访客可以查看完整正文及全部媒体。
4. 不知道密码的人只能在公开信息流看到脱敏预告卡片，无法获取真实内容和媒体。
5. 管理员在 `/me` 内管理和预览时不需要重复输入内容密码。
6. 保持当前单用户个人工具的短主路径，不引入访客账号、好友名单或权限组。

## 4. 非目标

首版不包含：

- 访客注册、登录和身份体系。
- 针对不同好友设置不同密码或不同权限。
- 按访问者撤销权限。
- 密码有效期、访问次数和阅后即焚。
- 访问记录、阅读回执和统计面板。
- 密码找回、验证码和额外的复杂密码强度策略。
- 端到端加密或数据库、文件的静态加密。

## 5. 核心交互

### 5.1 发布普通内容

“发布范围”从两项扩展为三项：

1. 公开：所有人可见，并进入公开信息流和订阅源。
2. 加密：公开列表只展示脱敏预告，知道密码的人可查看完整内容。
3. 私有：只在“我的全部记录”中可见。

选择“加密”后，在当前发布设置区域原位展开“访问密码”输入框：

- 密码固定为 6 位数字，只接受 `0-9`，允许以 `0` 开头。
- 输入框限制为 6 位，并在移动端唤起数字键盘。
- 提供显示或隐藏密码按钮。
- 密码不足或超过 6 位时，发布按钮不可用。
- 保存为草稿时仍按现有规则保持私有，不要求提前设置密码。
- 草稿正式发布时，才提交选择的范围和密码。

不增加独立向导或二次弹窗，避免把一次发布拆成多步。

### 5.2 发布和编辑文章

文章编辑器侧栏中的“可见范围”改为与普通内容一致的三项选择，并在选择“加密”时原位显示密码输入框。

新文章仍沿用现有“先保存文章，再设置访问范围”的主路径；保存完成后即可选择公开、加密或私有。已有文章可以在同一区域直接修改访问范围或密码。

### 5.3 加密已有内容

卡片和表格行的三点管理菜单中，将当前单一的公开/私有切换项改为“访问权限…”。点击后打开一个紧凑的访问权限弹窗：

- 选择公开、加密或私有。
- 选择加密时输入新密码。
- 当前为加密时显示“已设置访问密码”，但永不回显原密码。
- 当前为加密且不填写新密码时，保存其他内容不会修改密码。
- 点击“修改密码”后才出现新密码输入框。

访问权限弹窗只负责权限，不承载正文、标签或发布时间编辑。

### 5.4 分享

加密内容在管理菜单和编辑页提供“复制访问链接”。复制的仍是现有 `/p/:publicId` 地址，密码由管理员通过自己的沟通方式单独告知好友。

链接中不得携带密码，避免密码进入浏览器历史、聊天预览、服务器日志和第三方统计请求。

### 5.5 访客打开加密内容

访问加密详情时，页面公共框架立即展示，详情区域显示独立的密码访问卡片：

- 标题：“这是一条加密内容”。
- 说明：“请输入访问密码后查看”。
- 限制为 6 位数字并支持移动端数字键盘的密码输入框，以及“查看内容”按钮。
- 不提前展示真实标题、摘要、标签、封面或其他媒体。
- 密码错误时在输入框附近显示“访问密码不正确”，页面框架不重载。
- 验证成功后在当前地址原位展示完整详情，不跳转、不刷新整页。

同一浏览器成功解锁后，默认记住该条内容 30 天。在此期间再次打开同一链接可直接查看。

### 5.6 管理员访问

管理员登录状态优先于内容密码：

- 从 `/me` 打开加密内容时直接查看。
- 管理员直接访问 `/p/:publicId` 时也直接查看。
- 不为管理员创建或要求输入访客密码授权。

### 5.7 公开列表中的加密预告卡片

加密内容按原发布时间进入对应频道的公开时间线，但只渲染统一的锁定预告卡片：

- 卡片保留与当前瀑布流一致的图片区、圆角和上下信息结构，避免加密卡片成为突兀的纯文字块。
- 图片区使用项目内置的加密占位模板，不读取原图，也不使用原图的高斯模糊版本。
- 根据内容类型和 `publicId` 稳定选择占位模板，同一条内容每次展示保持一致，不同内容仍有视觉变化。
- 占位模板同时适配白天与深色模式，只表达“内容已锁定”，不包含真实内容文字或媒体特征。
- 文章频道显示“加密文章”，其他频道显示“加密记录”。
- 展示发布时间和锁形标识。
- 展示“输入密码查看”的行动提示。
- 不展示真实标题、正文摘要、标签、封面、图片、视频或文件信息。
- 点击卡片进入原 `/p/:publicId` 密码访问页。

加密预告卡片参与公开列表的正常分页，但不进入标签筛选结果。即使当前浏览器已经解锁该条内容，公开列表仍保持统一的脱敏卡片，避免列表接口产生两套缓存和数据形态。

#### 5.7.1 加密封面视觉系统

图片区不使用通用灰色占位块，而是设计为具有完整视觉表达的“加密封面”。首版提供 7 套模板，与当前纯文字画报已经建立的视觉语言保持协调，但不复用任何真实内容文字。

推荐的 7 套视觉方向：

1. 编辑纸张：中性纸张底色、细红线和低对比度几何水印。
2. 书页：暖色纸张、柔和书脊阴影和居中的锁形印记。
3. 瑞士网格：明确色块、粗线条和简洁编号元素。
4. 档案标签：档案纸纹理、编号章和克制的边角标记。
5. 影院渐变：深色渐变、柔和光晕和大尺寸半透明锁形轮廓。
6. 笔记纸：轻微横线、侧边强调线和手记式装饰符号。
7. 报刊排版：低对比度分栏线、刊头式结构和几何字标。

每套模板必须同时提供白天和深色模式：

- 白天模式使用低饱和纸张色、浅色纹理和深色锁形元素。
- 深色模式统一使用中性白作为主要文字和图标颜色，背景保持低亮度、低饱和度。
- 深色模式不是简单反相，需要单独控制背景、纹理、强调色和对比度。
- 模板之间允许风格差异，但锁形标识、信息层级和交互位置必须一致。

模板分配规则：

- 仅根据 `publicId` 计算稳定的模板序号，不读取标题、正文、标签、封面或媒体。
- 同一条内容在不同设备、刷新和分页后始终使用同一模板。
- 普通记录与文章共用模板池，但下方类型文案分别显示“加密记录”和“加密文章”。
- 模板选择不随内容解锁状态改变。

卡片结构：

- 加密封面占据当前卡片原本的媒体或画报区域。
- 瀑布流沿用当前媒体卡片的圆角、宽度和图片区比例，不增加卡片套卡片的外框。
- 文章列表沿用当前文章封面的区域尺寸，不强行套用瀑布流比例。
- 图片区中心或视觉重心位置展示锁形标识，可搭配 `PROTECTED` 或六个圆点等通用装饰，但不得出现真实内容。
- 图片区下方只保留“加密记录 / 加密文章”、“输入密码查看”和发布时间。
- 不展示摘要、标签、公开状态、原始文件类型或媒体数量。

视觉质量要求：

- 加密封面应看起来像主动设计的内容封面，而不是加载失败、骨架屏或图片缺失状态。
- 不使用高斯模糊、马赛克、原图色板、原图轮廓或从媒体派生的缩略图。
- 不使用闪烁、呼吸或循环动画吸引注意，避免破坏瀑布流阅读节奏。
- 锁形标识与背景保持足够对比度，卡片整体点击区域和现有公开卡片一致。
- 模板优先使用 CSS、项目现有字体和简单矢量装饰完成，不增加外部图片请求。

交互规则：

- 整张预告卡片均可点击，进入对应密码访问页。
- 桌面端沿用现有卡片悬停反馈，移动端不增加独立按钮层。
- 已解锁浏览器在公开列表中仍显示加密封面；进入详情后直接展示内容。
- 密码错误或权限失效只影响详情区域，不改变列表卡片布局。

## 6. 状态转换规则

| 原状态 | 目标状态 | 处理 |
| --- | --- | --- |
| 公开 | 加密 | 必须设置密码；公开卡片立即替换为脱敏预告卡片，并从订阅源消失 |
| 私有 | 加密 | 必须设置密码；原详情链接开始接受密码访问，并在对应公开频道出现脱敏预告卡片 |
| 加密 | 加密 | 可保持原密码，也可主动替换密码 |
| 加密 | 公开 | 清除密码；脱敏预告卡片恢复为完整公开卡片，并进入订阅源 |
| 加密 | 私有 | 清除密码；访客详情按不存在处理 |
| 公开 / 私有 | 公开 / 私有 | 沿用当前行为 |

修改加密内容的密码后，所有浏览器此前获得的访问权限立即失效，需要输入新密码。

删除加密内容时，沿用现有删除流程，正文、记录和媒体一并删除。

## 7. 管理端呈现

### 7.1 我的全部记录

- 加密内容显示独立的锁形图标和“加密”状态，不复用“私有”文案。
- 可见范围筛选增加“加密”。
- 表格与瀑布视图使用同一状态名称和颜色语义。
- 加密内容仍按原发布时间参与后台排序和搜索。
- 后台正文搜索和标签筛选可以正常查到加密内容。

### 7.2 公开区域

- 加密内容以脱敏预告卡片出现在对应频道的公开瀑布流或文章列表中。
- 预告卡片使用本地视觉模板填充图片区，不加载、派生或公开原始封面和媒体预览。
- 预告卡片只返回并展示公开标识、内容类型、发布时间和详情链接所需标识。
- 加密内容不进入公开标签筛选结果。
- 加密内容不进入 RSS 与 JSON Feed。
- 页面元信息不得包含内容标题、摘要、标签或封面。
- 加密访问页设置为不参与搜索引擎索引。

## 8. 密码与访问规则

1. 每条加密内容拥有一个独立密码。
2. 密码固定为 6 位数字，只接受 `0-9`，允许以 `0` 开头。
3. 不限制不同内容复用同一个密码。
4. 服务端只保存不可逆密码摘要，不保存和返回明文密码。
5. 密码比较必须在服务端完成。
6. 成功访问后发放仅对该条内容有效的签名访问凭证。
7. 访问凭证使用 HttpOnly、Secure 和 SameSite=Lax Cookie，默认有效 30 天。
8. 访问凭证必须包含内容标识和密码版本；密码变化后旧凭证自然失效。
9. 加密内容及其媒体响应使用私有、不可共享缓存策略。

首版不增加账号锁定、验证码或自建重试状态机。管理员需要为真正敏感的内容设置不易猜测的密码。

## 9. 内容与媒体访问完整性

权限判断必须覆盖同一条内容的所有出口：

- 普通文本详情。
- 富文本文章详情。
- 原图、视频和文件。
- 图片预览图。
- 文章封面与正文内图片。

不能只在前端隐藏内容。加密内容的正文数据和媒体二进制都必须由服务端根据管理员登录或该条内容的访问凭证放行。

## 10. 推荐的数据模型

在现有 `JournalEntry` 上扩展，不建立独立加密内容表：

- `visibility`：由 `private | public` 扩展为 `private | protected | public`。
- `access_password_hash`：仅加密内容有值。
- `access_revision`：密码变更时递增，用于让旧访问凭证失效。

约束：

- 只有已发布内容可以是 `protected`。
- `protected` 必须有密码摘要。
- `public` 和 `private` 不保留密码摘要。
- 状态转换不改变 `publicId`。

该模型可同时覆盖 Telegram 来源记录、Web 普通内容和 Web 富文本文章，不复制内容实体。

## 11. 推荐的接口行为

### 11.1 访客接口

- `GET /api/feed`
  - 公开内容：沿用完整的公开卡片数据。
  - 加密内容：返回独立的锁定卡片结构，仅包含 `publicId`、频道、文章或记录类型、发布时间和加密标识。
  - 前端只根据锁定卡片结构和 `publicId` 选择内置占位模板，接口不返回原始媒体地址、模糊图地址或可推导媒体特征的数据。
  - 不得先返回完整 `JournalEntry` 再由前端隐藏敏感字段。
  - 加密内容参与普通频道时间线分页，但不参与标签筛选。
- `GET /api/entries/:publicId`
  - 公开内容：返回完整内容。
  - 已解锁的加密内容：返回完整内容。
  - 未解锁的加密内容：返回明确的“需要访问密码”状态，不返回内容字段。
  - 私有或不存在：保持 404。
- `POST /api/entries/:publicId/unlock`
  - 接收符合 6 位数字格式的密码。
  - 成功时设置该条内容的访问凭证，并返回完整内容。
  - 密码错误时返回明确错误。

前端据此区分“链接不存在”和“需要密码”，不通过先下载完整内容再隐藏的方式实现。

### 11.2 管理接口

- 发布普通内容时，发布请求增加可选的访问密码；选择 `protected` 时必须提交 6 位数字密码。
- 管理端统一通过访问权限更新接口切换三种状态，并在设置或更换加密状态时提交新密码。
- 文章与普通内容复用同一条访问权限更新能力，不分别维护两套密码逻辑。

### 11.3 媒体接口

现有媒体接口需要从“公开或管理员”扩展为：

- 公开内容：任何人可访问。
- 加密内容：管理员或持有该条内容有效访问凭证的人可访问。
- 私有内容：仅管理员可访问。

## 12. 错误与边界行为

- 密码不是 6 位数字：管理端原位提示“请输入 6 位数字密码”，不能提交为加密状态。
- 密码错误：保留在密码访问页，不展示任何内容数据。
- 内容从加密转为私有：已经打开的访客再次请求正文或媒体时失去权限。
- 内容从加密转为公开：原链接继续有效，不再要求密码。
- 内容修改但密码未修改：已有访问凭证继续有效。
- 内容密码修改：已有访问凭证全部失效。
- 内容被删除：详情与媒体都不可继续访问。
- 复制旧媒体地址绕过详情页：仍需要同一条内容的有效访问权限。

## 13. 完整主路径

### 新建加密普通内容

```text
发布内容
→ 填写正文或添加媒体
→ 发布范围选择“加密”
→ 输入访问密码
→ 发布
→ 在我的全部记录中显示为“加密”
→ 复制访问链接并单独告知密码
```

### 加密已有文章

```text
进入文章编辑页
→ 文章设置选择“加密”
→ 输入访问密码
→ 保存访问权限
→ 原文章链接变为密码访问页
```

### 好友访问

```text
打开 /p/:publicId
→ 页面框架与密码访问卡片出现
→ 输入密码
→ 当前页面展示完整内容与媒体
→ 30 天内再次打开可直接查看
```

## 14. 验收条件

1. 普通内容和文章都能设置为公开、加密或私有。
2. 新建发布与已有内容修改都支持加密。
3. 设置、修改和输入访问密码时都只接受 6 位数字，并允许以 `0` 开头。
4. 加密内容会以统一的脱敏预告卡片出现在对应公开频道，并正常参与时间线分页。
5. 加密内容不会进入公开标签列表、RSS 和 JSON Feed。
6. 未输入正确密码时，除预告卡片允许的类型和发布时间外，正文、标题、标签、封面和媒体均不可获得。
7. 正确密码解锁后，无需刷新整页即可查看全部内容。
8. 同一浏览器在 30 天内可再次访问已解锁内容。
9. 修改密码后，旧访问权限立即失效。
10. 直接访问加密内容的图片、视频、预览图或文件时同样受到保护。
11. 管理员在 `/me` 中始终可以直接查看和管理加密内容。
12. 公开、加密、私有之间切换不改变原详情链接。

## 15. 修改量评估

修改量为中等偏大，但仍应作为现有内容可见性的一次纵向扩展完成，不需要新建子系统。

主要影响范围：

- SQLite 迁移与 `JournalEntry` 可见范围模型。
- Repository 的查询、写入、筛选和媒体权限数据。
- 公共详情解锁接口与访问凭证校验。
- 媒体原文件和预览文件权限。
- 普通内容发布器与文章编辑器的三态访问设置。
- `/me` 表格、瀑布卡片、筛选和管理菜单的加密状态。
- 公共详情页的密码访问状态。
- 公开列表增加脱敏的加密预告卡片结构，RSS 和 JSON Feed 继续只纳入 `public`。

实现时应复用现有 `JournalEntry`、`/p/:publicId` 和管理员登录判断，避免引入访客用户表、权限组、分享记录表或独立加密内容表。

## 16. Review 决策点

本方案推荐以下默认决策，Review 时只需确认是否接受：

1. 加密内容进入对应频道的公开列表，但只展示类型、发布时间、锁形标识和访问提示。决策：采用符合当前瀑布流视觉风格的内置占位模板，保留图片区和卡片结构；根据内容类型和 `publicId` 稳定选择模板，不读取原图，也不使用高斯模糊的原图。
2. 除预告卡片允许的内容类型和发布时间外，不泄露标题、摘要、标签、封面和媒体。 决策：符合现有视觉效果和逻辑即可
3. 每条内容使用一个固定 6 位数字密码，允许不同内容复用相同密码。 决策：允许
4. 解锁状态在当前浏览器保留 30 天。 决策：允许
5. UI 使用“加密”，技术边界是服务端密码访问控制，不做端到端加密。 决策：接受
