# V4.0 架构设计：常驻交互式全职管家 (Interactive Bot)

## 1. 架构愿景
将 NotiNewsForXiaoming 从目前的**“任务触发型 (Ephemeral)”** 升级为 **“常驻监听型 (Resident)”**。
核心目标是赋予机器人**“听”**和**“双向对话”**的能力，以实现高频、动态的自然语言提醒管理（如：“提醒我 10 分钟后去收衣服”、“明天下午 3 点提醒我开会”）。

## 2. 核心架构重构点

### 2.1 运行模式切换
*   **当前模式**：系统定时器 (Cron/Systemd) 唤醒 Node.js 进程 -> 执行一遍全量逻辑 -> 进程结束退出。
*   **新模式**：服务器通过 `pnpm start` 启动一个**永远在线**的 Node.js 进程。
    *   使用 Telegraf 的 `bot.launch()` 开启 Long-Polling（长轮询），实时接收 Telegram 消息。
    *   原有的固定时间推送任务（早报、晚报等）不再由系统 Cron 触发，而是集成到 Node.js 内部的定时器（如 `node-schedule`）中运行。

### 2.2 引入持久化存储 (Database)
既然是动态提醒，就必须有“记忆”，否则服务器一重启（或重新部署部署），未执行的提醒就会全部丢失。
*   **技术选型**：推荐使用 **SQLite** (`better-sqlite3` 库)。它是一个单文件数据库，无需额外部署 MySQL，极度轻量，非常适合个人 Bot。
*   **数据表设计** (`reminders`):
    *   `id`: 提醒唯一标识
    *   `chat_id`: 用户 ID（确保只提醒你）
    *   `content`: 提醒内容（如：去收衣服）
    *   `trigger_time`: 触发时间戳
    *   `status`: 状态（0: 待触发, 1: 已完成, 2: 已取消）

## 3. “动态提醒”功能实现链路

当你在 Telegram 发送一句：“10分钟后提醒我收衣服”：

### Step 1: 权限拦截器 (Middleware)
机器人收到消息后，首先比对发送者的 `chat_id` 是否等于 `.env` 中的 `TG_CHAT_ID`。如果不是，直接忽略（防白嫖和骚扰）。

### Step 2: 意图识别与解析 (AI Parser)
将你的自然语言发送给 DeepSeek，要求其提取结构化数据。
*   **Prompt 示例**:
    ```text
    提取下面这句话的提醒意图和时间，当前时间是 2026-05-03 22:00:00。
    输入：“10分钟后提醒我收衣服”
    请严格输出 JSON: {"is_reminder": true, "time": "2026-05-03 22:10:00", "task": "去收衣服"}
    ```
*   **解析结果**：拿到精确的绝对时间戳和任务内容。

### Step 3: 任务持久化与调度 (Storage & Scheduler)
1.  **入库**：将解析出的任务写入 SQLite 数据库。
2.  **加入内存调度器**：调用 `node-schedule` 或原生的 `setTimeout`（如果时间很短）将该任务挂载到内存中。
3.  **回复用户**：Bot 发送回执：“✅ 没问题，将在 22:10 提醒您：去收衣服”。

### Step 4: 触发提醒
时间到达，内存调度器唤醒：
1.  Bot 主动发送消息：“🔔 **提醒时间到！** 请去收衣服！”
2.  **附加交互**：消息下方带有两个 Inline Button：
    *   `[✅ 已完成]` -> 点击后更新数据库状态，Bot 回复“干得漂亮”。
    *   `[💤 再等5分钟]` -> 点击后，重新走 Step 3，将时间推迟 5 分钟。

## 4. 实施阶段规划 (Roadmap)

如果未来我们决定动工，建议分为以下三个阶段，确保平滑过渡：

*   **Phase 1: 基础重构 (平替当前功能)**
    *   引入 `node-schedule`。
    *   改写 `src/index.ts`，让原来的早报、健身等任务在常驻进程内按时触发。
    *   加入 `bot.launch()`，让进程保持存活。验证基础推送是否依然稳定。
*   **Phase 2: 对话引擎接入**
    *   接入 DeepSeek 作为自然语言处理中枢。
    *   实现文字消息监听，能够与 AI 进行简单的“一来一回”闲聊测试。
*   **Phase 3: 提醒中枢与数据库**
    *   引入 SQLite。
    *   完整实现上述的“意图解析 -> 入库 -> 调度 -> 提醒 -> 按钮反馈”链路。

## 5. 其他衍生玩法展望
一旦常驻后台打通，想象空间极大：
1.  **记账本**：对 Bot 说“今天打车 50 块”，它自动帮你归类存入数据库，月底输出图表。
2.  **快捷查询**：输入一个特定的游戏名，Bot 实时去查 IGN 评分发给你。
3.  **多轮健身指导**：在推送健身计划后，可以随时问它“引体向上做不了怎么办”，它能根据当天的上下文立刻回复“降阶动作”。
