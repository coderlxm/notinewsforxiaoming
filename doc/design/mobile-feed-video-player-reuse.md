# 信息流视频预加载与弹窗播放器复用方案

## 目标

消除移动端已经完成视频预加载后，打开详情弹窗仍短暂出现原生 loading 的现象。

改造后的主路径应为：

```text
视频卡片接近视口
→ 创建并预加载该视频对应的 HTMLVideoElement
→ 用户打开详情弹窗
→ 把同一个 HTMLVideoElement 挂载到弹窗媒体舞台
→ 直接静音播放
→ 关闭弹窗后暂停并保留该元素，供再次打开复用
```

核心约束是预加载和播放必须使用同一个 `HTMLVideoElement`。只复用 URL、HTTP 缓存或已建立的网络连接，仍然不能复用移动端播放器的 `readyState`、缓冲区、解码器和已解码首帧。

## 当前问题

当前实现存在两个互相独立的视频元素：

- `JournalProgressiveVideo.vue` 在卡片接近视口时创建一个脱离 DOM 的视频元素负责预加载。
- `JournalMediaStage.vue` 在弹窗打开后重新创建一个视频元素负责播放。

桌面浏览器可以较快地从 HTTP 缓存重新建立播放器，因此收益明显；移动端仍需为弹窗中的新元素初始化媒体管线并解码首帧，所以会短暂显示 loading。

## 方案选择

采用一个按视频 URL 管理的轻量播放器池，池中保存真实的 `HTMLVideoElement`，而不是保存“已经预加载”的布尔状态。

不采用以下方式：

- 不继续提前更多时间下载，因为它不能消除第二个播放器的初始化。
- 不把视频下载成 Blob，因为这会破坏 Range 流式加载并增加内存占用。
- 不调整媒体权限缓存头，因为即使完全命中缓存，新元素仍要重新初始化解码器。
- 不使用全局单例播放器，因为一个播放器只能同时预热一个视频，无法覆盖瀑布流中同时可见的多个视频。
- 不使用 Teleport 管理播放器所有权。视频元素由播放器池创建，不属于卡片 Vue 模板，因此可以直接、安全地在脱离状态和弹窗挂载点之间移动。

## 组件边界

### `journalVideoPlayerPool.ts`

新增一个纯媒体资源服务，负责：

- 按原始视频 URL 创建并保存唯一的 `HTMLVideoElement`。
- 设置 `preload="auto"`、`muted`、`playsInline` 和视频 URL。
- 通过引用计数管理卡片和弹窗对播放器的持有关系。
- 在最后一个持有者释放后停止加载、清空 URL 并移出播放器池。

建议暴露三个直接接口：

```ts
acquireJournalVideo(src: string): HTMLVideoElement
mountJournalVideo(src: string, target: HTMLElement): HTMLVideoElement
releaseJournalVideo(src: string): void
```

`acquireJournalVideo` 在播放器不存在时创建它，存在时直接返回同一个元素。`mountJournalVideo` 只负责把已有元素移动到目标容器，不重新设置 `src`，因此不会触发新的媒体加载流程。

### `JournalProgressiveVideo.vue`

继续只展示静态封面和播放图标。

当卡片进入现有的视口预热范围时：

- 调用 `acquireJournalVideo(src)`。
- 不再自行执行 `document.createElement('video')`。
- 组件销毁时释放自己的播放器引用。

卡片不挂载真实视频，也不改变当前点击行为。

### `JournalMediaStage.vue`

把 Vue 模板直接创建的 `<video>` 替换为一个稳定的媒体挂载容器。

弹窗媒体舞台出现时：

- 调用 `mountJournalVideo(currentAsset.url, container)`。
- 给返回的同一个视频元素开启 `controls` 和 `autoplay`。
- 如果播放器已经具备当前帧数据，立即显示并调用 `play()`。
- 如果从直接详情路由进入、此前没有卡片预加载，播放器池会在此创建播放器并沿正常加载主路径播放。

切换媒体或关闭弹窗时：

- 暂停当前视频。
- 将视频元素从舞台容器中移出，但不重设 `src`。
- 释放弹窗持有的引用；信息流卡片仍存在时，播放器及缓冲状态继续保留。

## 生命周期主路径

### 从信息流打开

1. 视频卡片进入视口预热范围。
2. 卡片取得播放器引用并开始预加载。
3. 用户点击卡片，详情弹窗挂载。
4. 媒体舞台按 URL 取得同一个播放器引用。
5. 播放器元素从脱离状态移动到舞台容器，原有 `readyState`、缓冲区和解码状态不变。
6. 视频静音自动播放。
7. 弹窗关闭后播放器暂停并脱离舞台；卡片仍持有它。

### 直接打开详情

1. 页面没有信息流卡片，也没有预加载播放器。
2. 媒体舞台取得 URL 时创建播放器。
3. 播放器按正常主路径加载并播放。
4. 详情关闭或页面离开后释放最后一个引用并销毁播放器资源。

### 多视频记录

每个视频 URL 对应独立播放器。切换媒体时释放当前弹窗引用，并挂载目标视频对应的播放器。已经在信息流中出现过的视频仍能复用其原有播放器；没有预热过的视频按直接打开详情的主路径加载。

## 样式处理

播放器元素由资源池创建，不会自动带上 Vue scoped CSS 属性。`JournalMediaStage.vue` 应给挂载容器设置现有舞台尺寸，并用容器后代选择器控制真实视频：

```css
.media-stage__video-host :deep(video) {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: contain;
}
```

这样播放器移动到舞台后仍沿用现有视觉尺寸、原生控制条和圆形视频样式，不需要把样式职责放进播放器池。

## 预期结果

- 桌面端保留当前预加载收益。
- 移动端打开弹窗时不再创建第二个播放器，也不再重复初始化媒体管线。
- 已预热视频可以直接进入静音播放，避免短暂原生 loading。
- 静态封面卡片、GIF 图片行为、多媒体切换和直接详情入口保持原有产品语义。
- 不需要修改服务端媒体缓存策略。
