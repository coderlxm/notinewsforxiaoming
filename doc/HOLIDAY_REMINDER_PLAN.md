# 法定节假日免打卡提醒方案（评审稿）

## 目标

在保留现有推送节奏的前提下，实现：

1. 周末不推送“打卡提醒”（当前已实现）。
2. 中国法定节假日不推送“打卡提醒”。
3. 对“调休上班日”仍推送“打卡提醒”。

说明：这里只控制“打工人日常提醒”模块，不影响天气、新闻、GitHub 趋势等主内容推送。

## 当前现状与问题

当前逻辑在 [src/formatters/index.ts](/Users/xiaomingli/Code/NotiNewsForXiaoming/src/formatters/index.ts) 中通过 `new Date().getDay()` 判断是否工作日。

存在两个问题：

1. 只能识别周一到周五，无法识别中国法定节假日和调休上班日。
2. 运行机器当前是 `PDT` 时区，`new Date()` 的日期语义可能与中国日期不一致，存在“日期跨天误判”风险。

## 推荐方案（方案 A）

采用“本地节假日数据文件 + 定时同步更新”的方式：

1. 在仓库维护一个年度日历文件（例如 `data/china-holiday-2026.json`）。
2. 推送时按 `Asia/Shanghai` 计算“今天中国日期”。
3. 通过日历判断当天是否是“上班日”，再决定是否附加“打卡提醒”。
4. 用一个轻量脚本按月/按季度更新下一年度节假日文件（可手动触发，也可后续挂到 deploy 或单独 workflow）。

选择理由：

1. 运行时不依赖第三方 API，稳定性高。
2. 对 Telegram 推送链路没有额外网络风险。
3. 规则可审计（哪个日期为何判断为休息日/上班日，一眼可见）。

## 维护方式（已确认）

采用“你不手工复制，我维护数据”的方式：

1. 我维护 `data/china-holiday-YYYY.json`（包含 `holiday_overrides`、`workday_overrides`）。
2. 每年国务院办公厅节假日通知发布后，我更新下一年度文件。
3. 你只需 review 一次关键日期（尤其调休上班日）即可。
4. 运行时业务代码只读取本地文件，不依赖在线 API。

## 数据模型建议

建议按“日期 -> 是否上班”建模，而不是只存“节假日列表”。

示例（仅示意）：

```json
{
  "timezone": "Asia/Shanghai",
  "year": 2026,
  "workday_overrides": ["2026-02-28"],
  "holiday_overrides": ["2026-02-17", "2026-10-01"]
}
```

规则：

1. 默认周一到周五视为上班日，周六周日视为休息日。
2. `holiday_overrides` 强制视为休息日（法定节假日）。
3. `workday_overrides` 强制视为上班日（调休补班）。

这样可覆盖所有法定安排，不依赖“节假日必须是周一到周五”的假设。
