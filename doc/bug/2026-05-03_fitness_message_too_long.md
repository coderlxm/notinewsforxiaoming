# 致命问题记录：健身私教消息超长导致推送失败

日期：2026-05-03（Asia/Shanghai）

## 问题级别

- 致命（功能不可用）

## 现象

- 本地强制触发健身模式后，Telegram 未收到消息。
- 日志显示：
  1. HTML 发送失败（解析失败后进入纯文本重试）
  2. 纯文本重试失败：`400 Bad Request: message is too long`

## 影响范围

- `fitness` 模式在 AI 输出过长时会直接发送失败。
- 用户侧表现为“完全收不到健身推送”。

## 触发条件

- AI 返回异常冗长内容（包含大段结构化文本，甚至完整 HTML/CSS 页面片段）。
- 在当前发送实现下，超长文本无法被 Telegram 单条消息接受。

## 根因

- 业务需求未对“健身私教输出长度与粒度”做硬约束（轻助手 vs 长文）。
- 发送层只有解析兜底，无长度治理策略（已按当前决策回退，不保留防过长逻辑）。

## 复现方式

```bash
TEST_MODE_ENABLED=1 TEST_FORCE_MODE=fitness pnpm start
```

出现 `message is too long` 即复现成功。

## 当前状态

- 已记录问题，等待重新评估“轻助手输出规范”后再设计修复方案。
- 相关临时“防过长输出”改动已按要求撤销。
